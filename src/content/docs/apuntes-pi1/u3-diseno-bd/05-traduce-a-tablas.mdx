## 📬 La idea en una frase

> Paso 3: cada entidad → una tabla, cada atributo → una columna, y las
> relaciones 1 a N → una clave foránea en la tabla "muchos". Con esas tres
> reglas, tu esquema se vuelve una base de datos de verdad.

Es como una hoja de cálculo bien hecha: un listado de usuarios con columnas
nombre, email y fecha; un listado de recetas con columnas título,
ingredientes y usuario. El archivo de cálculo que todo el mundo sabe usar es
la intuición perfecta para entender qué es una tabla: filas de datos
reales, columnas de atributos, y un encabezado que dice qué es cada cosa.

## 🔁 Paso 3: traduce a tablas

El folio de Laura se convierte en tres tablas:

| Entidad (del esquema) | Tabla (en la base de datos) |
|---|---|
| Usuario | `usuarios` |
| Receta | `recetas` |
| Comentario | `comentarios` |

Y cada atributo se convierte en una columna. El esquema del punto 04 queda
así:

```
TABLA: usuarios
id | nombre | email | password_hash | fecha_registro

TABLA: recetas
id | titulo | ingredientes | instrucciones | usuario_id | fecha

TABLA: comentarios
id | texto | usuario_id | receta_id | fecha
```

Fíjate en que las columnas `usuario_id`, `receta_id` no son inventos: son la
manera de que la tabla "muchos" recuerde a su padre. Son las **claves
foráneas**.

## 🔑 Qué es una clave foránea

Una **clave foránea** es una columna que guarda el `id` de otra tabla: es la
"etiqueta" que une cada fila con su padre. En `recetas`, la columna
`usuario_id` dice "esta receta pertenece al usuario con id 3". En
`comentarios`, las columnas `usuario_id` y `receta_id` dicen "este comentario
lo dejó el usuario 3 sobre la receta 12".

```
recetas
id | titulo      | usuario_id
1  | "Paella"    |    2       ◄── apunta a usuarios.id = 2
2  | "Bocata"    |    2
3  | "Sopa"      |    7
```

Gracias a esas etiquetas puedes responder preguntas que antes eran un caos:
"¿qué recetas ha publicado el usuario 2?", "¿qué comentarios tiene la receta
12?". Si una receta "pertenece" a un usuario, la clave foránea lo deja
escrito en piedra, y las favoritas de Laura no volverán a mezclarse.

## 🧩 El resultado: una base de datos coherente

Con las tres reglas cumplidas, tu base de datos ya tiene estructura:

| Entidad | Tabla | Clave primaria | Claves foráneas |
|---|---|---|---|
| Usuario | `usuarios` | `id` | — |
| Receta | `recetas` | `id` | `usuario_id` → usuarios |
| Comentario | `comentarios` | `id` | `usuario_id`, `receta_id` |

Las relaciones N a M que apuntaste en el punto 03 también se resuelven aquí:
se convierten en una **tabla intermedia** que conecta las dos tablas. Por
ejemplo, la relación "alumno ↔ asignatura" (N a M) genera una tabla
`matriculas` con dos claves foráneas: `alumno_id` y `asignatura_id`. Pero para
tu MVP, con 1 a N tienes de sobra.

## 🧠 Mini-chequeo

**Pregunta 1.** ¿Cómo se traduce una entidad al mundo de las bases de datos?
A) En una función · B) En una tabla · C) En un archivo de configuración.

**Pregunta 2.** Una clave foránea en `recetas` sirve para:
A) dar formato a la receta · B) guardar el `id` del usuario que creó la
receta · C) ocultar la receta de los buscadores.

**Pregunta 3.** Una relación N a M (alumnos ↔ asignaturas) se resuelve con:
A) una tabla intermedia con dos claves foráneas · B) borrando una de las dos
entidades · C) duplicando los alumnos en cada asignatura.

<details>
<summary>...Respuestas...</summary>

1. **B**. Cada entidad se convierte en una tabla; cada atributo, en una
   columna.
2. **B**. La clave foránea es la "etiqueta" que une cada receta con su usuario
   padre (recetas.usuario_id apunta a usuarios.id).
3. **A**. La tabla intermedia (por ejemplo `matriculas`) parte la N a M en dos
   relaciones 1 a N con dos claves foráneas.
</details>

## ✅ Resumen en 3 frases

1. Paso 3: cada entidad se vuelve una tabla y cada atributo una columna.
2. Las relaciones 1 a N se guardan como una clave foránea en la tabla
   "muchos": la etiqueta que recuerda a su padre.
3. Diseñar primero (una tarde) ahorra semanas frente al enfoque "sobre la
   marcha", que termina en laberinto.

> 🐛 **Vocabulario rápido**

| Término | Idea general |
|---|---|
| **Tabla** | La entidad hecha base de datos: filas de datos y columnas de atributos |
| **Columna** | Un atributo concreto de la tabla (nombre, email, fecha) |
| **Clave primaria** | El `id` único que identifica cada fila |
| **Clave foránea** | La columna que guarda el `id` del padre para unir las tablas |
| **Tabla intermedia** | Tabla puente para resolver relaciones N a M |
| **Base de datos** | El almacén organizado donde viven tus tablas |
