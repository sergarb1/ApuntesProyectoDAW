## 📬 La idea en una frase

> Un checklist no es burocracia: es **memoria externa**. Evita que te
  olvides de algo importante cuando estás centrado en otras cosas.
  Los pilotos lo usan. Los cirujanos lo usan. Tus equipos de DAW
  también deberían.

## ✅ El checklist completo

### Antes de empezar (primera semana del proyecto)

- [ ] **Tablero creado** con todas las tareas visibles (GitHub Projects, Trello, Notion o pizarra)
- [ ] **Columnas definidas**: al menos "Por hacer", "En proceso", "Hecho"
- [ ] **Cada tarea tiene**: nombre claro, responsable, estimación y prioridad
- [ ] **MVP identificado**: ¿qué es imprescindible para que el proyecto funcione?
- [ ] **Funcionalidades clasificadas**: Must / Should / Could / Won't (MoSCoW)
- [ ] **Herramienta de seguimiento elegida** y todos saben cómo usarla
- [ ] **Reuniones acordadas**: frequency, hora, duración, formato

### Cada sprint (cada 1-2 semanas)

- [ ] **Planning realizada** (30-45 min): ¿qué entra este sprint? ¿quién hace qué?
- [ ] **Tareas del sprint con estimación realista** (multiplicada por 2)
- [ ] **Tiempo disponible calculado**: ¿cuántas horas reales tiene el equipo?
- [ ] **El sprint cabe en el tiempo disponible**: si no, recortar antes de empezar
- [ ] **Dependencias identificadas**: ¿alguien necesita algo de otro para empezar?
- [ ] **Objetivo del sprint claro**: al final, ¿qué funcionará que antes no funcionaba?

### Durante el sprint (cada día)

- [ ] **Daily realizada** (15 min): ¿qué hice? ¿qué haré? ¿qué me bloquea?
- [ ] **Tablero actualizado**: cada persona mueve sus tarjetas
- [ ] **WIP respetado**: máximo 2-3 tareas en proceso por persona
- [ ] **Bloqueos comunicados**: si algo no avanza, se dice en la daily, no se esconde

### Al final del sprint (cada 1-2 semanas)

- [ ] **Revisión**: ¿qué se terminó? ¿qué funciona? ¿qué falta?
- [ ] **Retrospectiva**: ¿qué funcionó? ¿qué no? ¿qué cambiamos?
- [ ] **Tablero revisado**: ¿hay tarjetas en "En proceso" más de 3 días?
- [ ] **Siguiente sprint planificado**: ¿qué entra ahora? ¿hay recortes?

### Si vas retrasado (cuando lo detectes)

- [ ] **Priorizar**: ¿qué es realmente MVP? (punto 05)
- [ ] **Recortar**: lo que no sea imprescindible, fuera (punto 06)
- [ ] **Simplificar**: una versión simple que funcione (punto 06)
- [ ] **Pedir ayuda**: al profesor o a compañeros (punto 06)
- [ ] **Comunicar al equipo**: "no llegamos, esto es lo que propongo"

### Check final (antes de la entrega)

- [ ] **Todas las funcionalidades MVP** funcionan y están probadas
- [ ] **No hay errores críticos** abiertos en el tablero
- [ ] **Documentación** actualizada (README, instrucciones de uso)
- [ ] **Demo preparada**: ¿qué vais a mostrar al tribunal?
- [ ] **Responsable de cada entregable**: ¿quién sube qué?

## 🧩 Cómo usar el checklist en la práctica

### Opción 1: Pegado en la pared

Imprímelo. Pégalo donde el equipo se reúne. Cada lunes, marcáis con
rotulador los puntos completados.

### Opción 2: En el tablero como tarea

Añadid el checklist como una tarjeta "eterna" en el tablero. Cada
sprint, la revisáis y marcáis lo que ya tenéis como hábito.

### Opción 3: En Notion o Google Docs

Crear un documento compartido con el checklist. Cada sprint, copiad
el documento y marcáis. Así tenéis historial de sprints anteriores.

### Opción 4: Template de GitHub Issues

Crear una issue template con el checklist. Cada sprint, crear una issue
nueva con el template y marcar los puntos.

<Aclaracion pregunta="¿No es demasiado para un proyecto de clase?">
  El checklist tiene **19 puntos** para la primera semana, **6 por sprint**
  y **5 diarios**. En total, revisar el checklist completo te lleva
  **5 minutos por semana**.

  Compara eso con las horas que ahorras por no olvidar cosas: actualizar
  el tablero, estimar correctamente, comunicar bloqueos, recortar a tiempo.

  5 minutos de checklist = horas de trabajo ahorrado.
</Aclaracion>

## 🧩 Mini-checklist rápido

Si el checklist completo es demasiado, usa este **mini-checklist de
5 puntos** que cubre lo esencial:

```
CADA SEMANA, RESPONDE:
1. ¿Sé exactamente qué hago esta semana?
2. ¿El tablero está actualizado?
3. ¿Sé cuántas horas tengo y cuánto falta?
4. ¿He dicho a mi equipo si voy retrasado?
5. ¿Algo funciona esta semana que antes no funcionaba?
```

Si la respuesta a alguna es "no", **actúa antes de mañana**.

## ✅ Resumen en 3 frases

1. El checklist combina **todo lo aprendido** en esta unidad: tablero,
   estimación, priorización, reuniones y seguimiento.
2. Úsalo **cada lunes** (planning), **cada día** (daily + tablero) y
   **al final del sprint** (revisión + retrospectiva).
3. Si el completo es mucho, usa el **mini-checklist de 5 preguntas**:
   ¿sé qué hago? ¿tablero actualizado? ¿horas calculadas? ¿bloqueos
   comunicados? ¿algo funciona que antes no?
