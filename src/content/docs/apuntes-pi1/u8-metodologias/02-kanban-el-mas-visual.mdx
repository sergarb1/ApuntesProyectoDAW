## 📬 La idea en una frase

> Un tablero Kanban es un **mapa visual del trabajo**: columnas que
> representan estados, tarjetas que representan tareas. Mueves la tarjeta
> de izquierda a derecha cuando avanzas. Si no puedes moverla, hay un
> problema que ver.

## 📊 Las columnas básicas

El tablero mínimo tiene tres columnas:

```
┌─────────────┬─────────────┬─────────────┐
│  POR HACER  │ EN PROCESO  │   HECHO     │
├─────────────┼─────────────┼─────────────┤
│ CRUD users  │ Login       │ Diseño BD   │
│ Inicio      │ Perfil      │ Prototipo   │
│ Tests       │             │ Setup repo  │
└─────────────┴─────────────┴─────────────┘
```

Cada tarjeta es una tarea concreta. Cuando empiezas a trabajar en ella,
la mueves a "En proceso". Cuando la terminas (de verdad, no "más o menos"),
la mueves a "Hecho".

### Columnas opcionales según el proyecto

| Columna | Cuándo usarla |
|---|---|
| **Backlog** | Tareas ideas que aún no se han priorizado |
| **Bloqueado** | Tareas que no avanzan porque dependen de otra persona o cosa |
| **En revisión** | Tareas terminadas esperando code review |
| **Desplegado** | Funcionalidades ya en producción o en el servidor de pruebas |

## 🃏 Las tarjetas: qué poner en cada una

Una tarjeta bien hecha tiene:

```
┌─────────────────────────────────────┐
│ 🔴 Alta · Asignada: Javi           │
│                                      │
│ Login con validación de email        │
│                                      │
│ - Maquetar HTML (2h)                │
│ - Estilos CSS (1h)                  │
│ - Validación JS (2h)                │
│ - Conectar con API (2h)             │
│ - Probar (1h)                       │
│                                      │
│ Fecha límite: 15 marzo              │
│ Estado: En proceso                  │
└─────────────────────────────────────┘
```

**Qué debe tener**:
- **Nombre claro**: "Login con validación de email", no "login"
- **Responsable**: quién la hace (una sola persona)
- **Estimación**: cuánto cree que llevará
- **Subtareas** (opcional): desglose de la tarea
- **Prioridad**: alta / media / baja
- **Fecha límite**: cuándo debería estar lista

## ⚠️ Límites WIP: el secreto que nadie te cuenta

**WIP** = Work In Progress = "trabajo en progreso".

La regla Kanban más importante: **no tener demasiadas tarjetas en "En proceso"
a la vez**.

| Equipo sin WIP | Equipo con WIP limit = 2 por persona |
|---|---|
| Javi tiene 5 tareas en proceso | Javi tiene como máximo 2 tareas en proceso |
| Ninguna se termina nunca | Termina una antes de empezar otra |
| Sensación de "todo a medias" | Sensación de "voy avanzando" |
| Al final, nada está listo | Cada día algo pasa a "Hecho" |

**Regla práctica**: si una persona tiene más de 2-3 tareas en proceso,
está multihaciendo y no está terminando nada.

## 🛠️ Herramientas para montar tu tablero

### GitHub Projects (recomendada para DAW)

- Integrada con el repositorio del proyecto
- Puedes crear tarjetas desde issues
- Vista de tablero (kanban) y vista de tabla
- Filtros por responsable, etiqueta, sprint
- **Gratis** para estudiantes

### Trello

- Muy visual e intuitivo
- Ideal para empezar rápido
- Etiquetas de color, fechas, checklists
- Sin integración directa con Git

### Notion

- Tableros + wiki + documentación en uno
- Más potente pero más complejo
- Bueno si ya usáis Notion para otras cosas

### Pizarra física

- Sticky notes en una pared
- Perfecta para reuniones presenciales
- Sin historial ni seguimiento automático
- Complemento ideal del tablero digital

<Aclaracion pregunta="¿Cuál debería usar mi equipo?">
  Si ya tenéis repositorio en **GitHub**, usad **GitHub Projects**: está
  integrada, es gratis y tenéis todo en un sitio.

  Si necesitáis algo más visual o no usáis GitHub, **Trello** es la opción
  más rápida para empezar.

  Lo peor que podéis hacer: **no usar ninguna**. Un tablero en WhatsApp
  no es un tablero: es un chat donde se pierde la información.
</Aclaracion>

## 🧩 Cómo mover las tarjetas: reglas simples

1. **Solo el responsable** mueve su tarjeta.
2. **No muevas a "Hecho" sin que esté realmente terminada** (probada, sin
   errores visibles, cumpliendo lo que pedía).
3. **Si una tarjeta lleva más de 3 días en "En proceso"**, algo bloquea:
   hablalo en la daily.
4. **Si "En proceso" está atascada** (muchas tarjetas, pocas salen),
   reducid WIP o dividid las tareas en más pequeñas.
5. **Revisad el tablero al menos 2 veces por semana** en reunión de equipo.

## 🧠 Mini-chequeo

**Pregunta 1.** ¿Cuántas tarjetas en "En proceso" debería tener como
máximo una persona?
A) Las que pueda · B) 2-3 como máximo · C) 10-15 · D) No importa

**Pregunta 2.** Una tarjeta lleva 5 días en "En proceso". ¿Qué haces?
A) Nada, es normal · B) La mueves a "Hecho" para que el tablero se vea
   mejor · C) Hablas en la daily para ver qué la bloquea · D) La borras

<details>
<summary>...Respuestas...</summary>

1. **B**. El límite WIP de 2-3 por persona evita la multitarea ineficiente
   y garantiza que algo se termine cada día.
2. **C**. Si una tarjeta se atasca, hay un bloqueo que hay que identificar
   y resolver. No la muevas a "Hecho" sin que esté lista.

</details>

## ✅ Resumen en 3 frases

1. Un tablero Kanban tiene columnas (Por hacer → En proceso → Hecho) y
   tarjetas que se mueven de izquierda a derecha.
2. El **límite WIP** (2-3 tarjetas por persona en proceso) es la regla
   más importante: evita multitarea y garantiza que algo se termine.
3. GitHub Projects, Trello, Notion o una pizarra física: todas valen,
   pero **tened alguna**. Lo que no está visible no existe.

> 🐛 **Vocabulario rápido**

| Término | Idea general |
|---|---|
| **Kanban** | Método visual de gestión: tablero con columnas y tarjetas que fluyen |
| **WIP** | Work In Progress: trabajo en progreso simultáneo (limitarlo es clave) |
| **Tarjeta** | Representación de una tarea concreta en el tablero |
| **Backlog** | Lista de tareas pendientes que aún no se han empezado |
| **Columna "Bloqueado"** | Tareas que no avanzan por dependencia externa |
