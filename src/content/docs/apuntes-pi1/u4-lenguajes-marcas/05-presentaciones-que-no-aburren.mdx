## 📬 La idea en una frase

> En el primer minuto de tu presentación, el tribunal decide si le interesa
> tu proyecto. No empieces con "Bueno, nosotros hemos hecho…": empieza con
> el problema, la solución o una demo.

Es como el tráiler de una película: no te cuentan el argumento completo, te
muestran lo mejor y te hacen querer ver el resto. Tu presentación es el
tráiler de cuatro meses de trabajo.

## ⏱️ La regla del minuto inicial

En el primer minuto de tu presentación, el tribunal decide si le interesa tu
proyecto. No es un juicio definitivo, pero sí una primera impresión que luego
cuesta mover. Por eso el arranque no se improvisa: se prepara y se ensaya.

Dos cosas matan el primer minuto:

- "Bueno, nosotros hemos hecho una aplicación sobre..."
- "Nuestro proyecto trata de..."

Son frases vacías: no dicen qué problema, ni para quién, ni por qué importa.
El tribunal escucha "otra app más" y desconecta.

## 🚫 No empieces así

| Forma de empezar | Qué transmite |
|---|---|
| "Bueno, nosotros hemos hecho una aplicación sobre..." | Aburrimiento, sin problema ni propósito |
| "Nuestro proyecto trata de..." | Lo mismo: describe el objeto, no la necesidad |
| "Hemos usado React y Node" (primera diapositiva) | Tecnología sin contexto; el tribunal aún no sabe el qué |

Estos arranques no son "malos" porque sean incorrectos: son malos porque
queman el minuto que decide si alguien te sigue escuchando. Ese minuto es de
oro.

## ✅ Empieza con problema, solución o demo

En vez de describir, **cuenta el problema**. Tres arranques que funcionan:

- **El problema**: "Cada año, los estudiantes de DAW pierden apuntes..."
- **La solución**: "Por eso hemos creado una plataforma donde..."
- **Una demo rápida**: "Enseñémoslo ya"

```
ARQUITECTURA DEL PRIMER MINUTO
──────────────────────────────
1. FRASE DEL PROBLEMA   → "Cada año, los estudiantes de DAW pierden apuntes..."
2. FRASE DE LA SOLUCIÓN → "Por eso hemos creado una plataforma donde..."
3. (OPCIONAL) DEMO      → "Enseñémoslo ya"
```

Fíjate en que en los tres casos hablas de **personas y necesidades**, no de
tecnología. El tribunal engancha con el qué y el para quién; la tecnología
viene después.

## 🎬 Del papel a la práctica

<CasoPractico titulo="Dos arranques, el mismo proyecto">

  Proyecto: app para gestionar el préstamo de libros de una biblioteca.

  **Arranque A (aburrido):** "Bueno, nosotros hemos hecho una aplicación
  sobre bibliotecas. Tiene varios módulos, un CRUD de libros y un sistema de
  préstamos. Hemos usado..." El tribunal mira el reloj.

  **Arranque B (que engancha):** "En esta biblioteca, cada semana se pierden
  una media de 30 libros porque el préstamo se apunta en una libreta. Hemos
  creado una aplicación que registra cada préstamo en dos segundos y avisa
  cuando un libro no se devuelve. Enseñémoslo ya."

  Mismo proyecto, misma tecnología. El segundo arranque cuenta un problema
  concreto y promete enseñarlo: el tribunal quiere ver el resto.
</CasoPractico>

<Aclaracion pregunta="¿Y si mi proyecto no tiene un problema que duela?">
  Todo proyecto escolar nace de algún problema, aunque sea pequeño: apuntes
  que se pierden, tareas que se olvidan, listas que se desordenan. Si no
  encuentras el problema, pregúntate qué pasaba ANTES de tu proyecto: eso es
  el dolor que estás aliviando. Si de verdad no existe, quizá el proyecto
  necesita un problema que lo justifique (revísalo con tu profesor).
</Aclaracion>

## 🧠 Mini-chequeo

**Pregunta 1.** El mejor primer minuto de una presentación:
A) lista todas las tecnologías usadas · B) cuenta un problema concreto y
promete una solución · C) agradece al profesor por la oportunidad.

**Pregunta 2.** "Nuestro proyecto trata de..." es un mal arranque porque:
A) es falso · B) describe el objeto, no la necesidad · C) es demasiado corto.

<details>
<summary>...Respuestas...</summary>

1. **B**. Problema concreto + promesa de solución (o demo) engancha.
2. **B**. Describe lo que construiste, no por qué importa: quema el minuto
   que decide si alguien te sigue escuchando.
</details>

## ✅ Resumen en 3 frases

1. En el primer minuto el tribunal decide si tu proyecto le interesa: ese
   minuto se prepara y se ensaya.
2. No empieces con "Bueno, nosotros hemos hecho...": empieza con el problema,
   la solución o una demo.
3. Habla de personas y necesidades antes que de tecnología: el qué engancha,
   el cómo se explica después.

> 🐛 **Vocabulario rápido**

| Término | Idea general |
|---|---|
| **Regla del minuto inicial** | El primer minuto decide si el tribunal se interesa por tu proyecto |
| **Enganchar** | Conseguir que quien te escucha quiera saber más |
| **CRUD** | Crear, leer, actualizar y borrar: las operaciones básicas sobre datos |
| **Arranque** | Las primeras frases de tu presentación, que no se improvisan |
| **Demo** | Mostrar la aplicación funcionando en directo |
