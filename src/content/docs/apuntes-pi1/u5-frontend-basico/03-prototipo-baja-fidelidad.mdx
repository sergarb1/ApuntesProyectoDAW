  Este capítulo te enseña a **dibujar antes de codificar**. Un prototipo de
  baja fidelidad (wireframe) es un boceto rápido: cajas, flechas, palabras.
  Sin colores, sin fuentes, sin código. Solo estructura. Cambiar un trazo
  en papel cuesta segundos; cambiar HTML y CSS cuesta horas.

## 📬 La idea en una frase

> El prototipo de baja fidelidad es tu plano de obra. No empieces a levantar
> paredes sin saber dónde van las puertas.

Es como hacer la lista de la compra antes de ir al supermercado. Si vas sin
lista, compras cosas que no necesitas y olvidas la leche. El wireframe es
tu lista: qué pantallas, qué hay en cada una, cómo se conectan.

## 🎯 Qué es y qué NO es un wireframe

| Wireframe SÍ es | Wireframe NO es |
|---|---|
| Estructura de la pantalla | Diseño visual final |
| Jerarquía de información | Paleta de colores |
| Navegación entre pantallas | Tipografías exactas |
| Contenido real (textos aproximados) | Imágenes finales |
| Hecho en 10-30 min por pantalla | Pixel-perfect |

**Herramientas recomendadas** (todas gratuitas para uso educativo):
- **Papel y boli** (la más rápida, la mejor para empezar).
- **Excalidraw** — online, a mano alzada, colaborativo.
- **Balsamiq** — estilo "boceto", librería de componentes UI.
- **Figma** — también para baja fidelidad (modo "wireframe").
- **Draw.io / diagrams.net** — diagramas y wireframes simples.

## 🧱 Qué debe tener cada wireframe

Para cada pantalla, dibuja y etiqueta:

1. **Título de la pantalla** (qué es).
2. **Cabecera / navegación** (logo, menú, usuario).
3. **Zona de contenido principal** (lista, formulario, detalle).
4. **Acciones primarias** (botón "Crear", "Guardar", "Buscar").
5. **Acciones secundarias** (enlaces, filtros, paginación).
6. **Estados vacíos** (qué se ve si no hay datos).
7. **Estados de error** (dónde aparece el mensaje).
8. **Flechas de navegación** (a qué pantalla va cada botón/enlace).

```
┌─────────────────────────────────────┐
│ 🏠 Inicio      [Buscar...]   👤 Ana │  ← Cabecera
├─────────────────────────────────────┤
│                                     │
│  ┌─ Mis tareas ──────────────────┐  │  ← Título sección
│  │ ☐ Comprar leche        [✏️]   │  │
│  │ ☐ Llamar a mamá        [✏️]   │  │  ← Lista con acciones
│  │ ☑ Entregar proyecto    [🗑️]   │  │
│  └──────────────────────────────┘  │
│                                     │
│  [+ Nueva tarea]              (FAB) │  ← Acción principal
│                                     │
└─────────────────────────────────────┘
```

## 🔗 El mapa de navegación

Además de los wireframes por pantalla, haz un **mapa de navegación**: un
diagrama que muestre cómo se conectan las pantallas.

```
[Login] ──► [Dashboard] ──► [Lista tareas] ──► [Detalle tarea]
                │              │
                │              └──► [Editar tarea]
                │
                └──► [Perfil] ──► [Editar perfil]
                │
                └──► [Ajustes]
```

Este mapa te sirve para:
- Detectar pantallas huérfanas (nadie llega a ellas).
- Ver si hay bucles imposibles.
- Contar pantallas reales (para estimar tiempo).

## 🧩 Caso práctico: la app de tareas

<CasoPractico titulo="Wireframes que salvaron el proyecto">

  **Equipo Sin Wireframes:**
  - Empezaron a codificar el login el día 1.
  - Día 10: se dan cuenta de que falta "recuperar contraseña".
  - Día 15: el dashboard no tiene acceso a "ajustes".
  - Día 20: reescriben la navegación tres veces.
  - **Total interfaz: 4 semanas, 3 reescrituras.**

  **Equipo Con Wireframes:**
  - Día 1-2: dibujan 8 pantallas + mapa navegación en Excalidraw.
  - Día 3: validan con el profesor ("falta recuperar contraseña", "añade
    breadcrumb en detalle"). Corrigen en papel: 10 minutos.
  - Día 4-14: codifican sobre plano fijo. Cero reescrituras de estructura.
  - **Total interfaz: 2 semanas, 0 reescrituras.**

  **Lección:** el tiempo que "pierdes" dibujando lo ganas multiplicado
  codificando.

</CasoPractico>

## 🧠 Mini-chequeo

**Pregunta 1.** En un wireframe de baja fidelidad, ¿qué NO debe aparecer?
A) Jerarquía visual · B) Colores corporativos exactos · C) Navegación entre
   pantallas · D) Acciones principales.

**Pregunta 2.** Tu wireframe tiene una pantalla "Detalle tarea" pero en el
mapa de navegación ninguna flecha llega a ella. ¿Qué significa?
A) Es una pantalla secreta · B) Es una pantalla huérfana: el usuario no
   puede llegar · C) Es opcional · D) El mapa está mal.

<details>
<summary>...Respuestas...</summary>

1. **B**. Los colores exactos son diseño visual (alta fidelidad), no
   wireframe. 2. **B**. Pantalla huérfana = código muerto. Corrige el mapa
   o borra la pantalla.

</details>

## ✅ Resumen en 3 frases

1. Dibuja antes de codificar: un wireframe en papel cuesta minutos; reescribir
   HTML cuesta horas.
2. Cada wireframe necesita: título, cabecera, contenido, acciones primarias/
   secundarias, estados vacíos, errores y flechas de navegación.
3. El mapa de navegación revela pantallas huérfanas y bucles antes de que
   existan en código.

> 🐛 **Vocabulario rápido**

| Término | Idea general |
|---|---|
| **Wireframe / Prototipo baja fidelidad** | Boceto estructural de una pantalla sin diseño visual |
| **Alta fidelidad** | Maqueta con colores, tipografías, imágenes finales |
| **Mapa de navegación** | Diagrama de cómo se conectan las pantallas |
| **Pantalla huérfana** | Pantalla a la que no se puede llegar desde ninguna otra |
| **Estado vacío** | Qué se muestra cuando no hay datos (lista vacía, sin resultados) |
