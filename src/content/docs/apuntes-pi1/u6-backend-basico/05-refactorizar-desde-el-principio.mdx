## 📬 La idea en una frase

> La refactorización constante es como lavar los platos mientras cocinas: si
> esperas a terminar la cena, la pila es inmanejable. Si limpias a medida que
> vas, la cocina sigue usable.

## 🚫 El mito de "refactorizo al final"

"Ya limpiaré cuando termine" es la mentira que más proyectos hunde. Al final:

- No hay tiempo (la entrega es mañana).
- No te acuerdas por qué hiciste cada cosa.
- Tienes miedo a tocar código que "funciona" (aunque sea frágil).
- La deuda técnica se paga con intereses: cada cambio nuevo cuesta más.

**La refactorización no es una fase: es un hábito.**

## 🔍 Cuándo refactorizar (señales de alarma)

| Señal | Qué significa | Acción inmediata |
|---|---|---|
| **Copia-pega** | Mismo código en 2+ sitios | Extraer a función/utilidad |
| **Función > 30-40 líneas** | Hace demasiadas cosas | Dividir en funciones pequeñas |
| **Niveles de anidamiento > 3** | `if` dentro de `if` dentro de `if` | *Early returns*, extraer lógica |
| **Parámetros > 3-4** | La función sabe demasiado | Agrupar en objeto / dividir |
| **Comentarios "hace X"** | El código no se explica solo | Renombrar variable/función |
| **Magic numbers/strings** | `if (status === 2)` ¿qué es 2? | Constante con nombre semántico |

## 🛠️ Técnicas de refactorización básica (catálogo mínimo)

### 1. Extraer función (Extract Function)
```javascript
// ANTES: duplicado en 3 controladores
if (!usuario || !usuario.activo) {
  return res.status(401).json({ error: 'No autorizado' });
}

// DESPUÉS: en utils/auth.utils.js
export function requerirUsuarioActivo(usuario, res) {
  if (!usuario || !usuario.activo) {
    res.status(401).json({ error: 'No autorizado' });
    return false;
  }
  return true;
}

// USO
if (!requerirUsuarioActivo(usuario, res)) return;
```

### 2. Early Return (Guard Clauses)
```javascript
// ANTES: anidamiento profundo
function procesarPedido(pedido) {
  if (pedido) {
    if (pedido.items.length > 0) {
      if (pedido.cliente.activo) {
        // ... 50 líneas de lógica
      }
    }
  }
}

// DESPUÉS: guard clauses al principio
function procesarPedido(pedido) {
  if (!pedido) return;
  if (pedido.items.length === 0) return;
  if (!pedido.cliente.activo) return;

  // ... lógica principal a nivel 0
}
```

### 3. Reemplazar magic numbers/strings por constantes
```javascript
// ANTES
if (estado === 2) { ... }  // ¿qué es 2?

// DESPUÉS: en config/estados.config.js
export const ESTADO_PEDIDO = {
  PENDIENTE: 1,
  CONFIRMADO: 2,
  ENVIADO: 3,
  ENTREGADO: 4,
  CANCELADO: 5
};

// USO
if (estado === ESTADO_PEDIDO.CONFIRMADO) { ... }
```

### 4. Dividir función grande (Split Function)
```javascript
// ANTES: 120 líneas
async function crearUsuarioConTodo(datos) {
  // validar
  // hashear password
  // guardar en BD
  // enviar email bienvenida
  // crear registro auditoría
  // devolver usuario
}

// DESPUÉS: funciones pequeñas, cada una testeable
async function crearUsuario(datos) {
  const validados = validarDatosUsuario(datos);
  const conHash = await hashearPassword(validados);
  const usuario = await guardarUsuario(conHash);
  await enviarEmailBienvenida(usuario.email);
  await auditoria.registrar('USUARIO_CREADO', usuario.id);
  return usuario;
}
```

## ¿Y si refactorizo y rompo algo que funcionaba?

<Aclaracion pregunta="¿Y si refactorizo y rompo algo que funcionaba?">

  Por eso **refactorizas en pasos tiny** y **pruebas después de cada paso**.
  1. Haces UN cambio pequeño (extraer función, renombrar).
  2. Pruebas a mano / corres tests.
  3. Si pasa → commit. Si falla → reviertes (git checkout).
  
  Con commits atómicos y pruebas constantes, el riesgo es casi cero. Y si algo
  se rompe, sabes exactamente qué cambio lo rompió (el último commit).

</Aclaracion>

## ✅ Resumen en 3 frases

1. **Refactorizar no es una fase final: es un hábito continuo.** Limpia cada
   vez que ves duplicación, función larga o anidamiento profundo.
2. Técnicas mínimas: **extraer función, early returns, constantes semánticas,
   dividir funciones grandes**. Cada una tarda minutos.
3. Refactoriza en **pasos tiny + prueba + commit**. Si rompes, reviertes el
   último commit y sabes exactamente qué fue.

> 🐛 **Vocabulario rápido**

| Término | Idea general |
|---|---|
| **Refactorización** | Cambiar estructura interna sin cambiar comportamiento externo |
| **Deuda técnica** | Coste futuro de mantener código sucio / duplicado / frágil |
| **Extract Function** | Llevar código repetido a una función reutilizable |
| **Guard Clause / Early Return** | Validar y salir pronto para aplanar anidamiento |
| **Magic number** | Número literal sin nombre que oculta significado (ej. `estado === 2`) |
