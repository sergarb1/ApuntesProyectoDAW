## La idea en una frase

> API-first significa: primero define qué hace tu API (el contrato),
> después escribe el código que la cumple. Es como planear un viaje
> antes de meterte en el coche.

## El enfoque API-first

El enfoque tradicional es:

```
1. Programar el backend
2. Probar que funciona
3. Decirle al frontend qué endpoints hay
4. El frontend se adapta
```

El enfoque API-first es:

```
1. Definir la API (contrato)
2. Frontend y backend programan en paralelo contra ese contrato
3. Cuando ambos están listos, se conectan
```

### Por qué API-first es mejor

| Enfoque | Ventaja | Riesgo |
|---------|---------|--------|
| Tradicional | El backend define todo | El frontend espera y luego adivina |
| API-first | Ambos trabajan en paralelo | Requiere definir bien el contrato al inicio |

## OpenAPI: el estándar para documentar APIs

OpenAPI (antes Swagger) es un formato estándar para describir APIs.
Se escribe en YAML o JSON y define:

- **Información general**: nombre, versión, descripción
- **Endpoints**: cada URL y su método
- **Parámetros**: qué datos acepta cada endpoint
- **Respuestas**: qué devuelve cada endpoint
- **Esquemas**: la estructura de los datos (modelos)

### Ejemplo de especificación OpenAPI

```yaml
openapi: 3.0.0
info:
  title: API de Tareas
  version: 1.0.0
paths:
  /api/v1/tareas:
    get:
      summary: Lista todas las tareas
      parameters:
        - name: page
          in: query
          schema:
            type: integer
      responses:
        '200':
          description: Lista de tareas
          content:
            application/json:
              schema:
                type: object
                properties:
                  data:
                    type: array
                    items:
                      $ref: '#/components/schemas/Tarea'
    post:
      summary: Crea una tarea nueva
      requestBody:
        required: true
        content:
          application/json:
            schema:
              type: object
              required:
                - titulo
              properties:
                titulo:
                  type: string
                descripcion:
                  type: string
      responses:
        '201':
          description: Tarea creada

components:
  schemas:
    Tarea:
      type: object
      properties:
        id:
          type: integer
        titulo:
          type: string
        completada:
          type: boolean
```

### Ventajas de OpenAPI

1. **Documentación automática**: herramientas como Swagger UI la convierten
   en una web interactiva.
2. **Mocks**: el frontend puede simular respuestas sin backend.
3. **Validación**: puedes comprobar que tu API cumple el contrato.
4. **Contrato vivo**: se actualiza con el código y siempre está sincronizado.

## Swagger UI: documentación interactiva

Swagger UI es una herramienta que toma tu especificación OpenAPI y genera
una web donde puedes:

- Ver todos los endpoints
- Probar cada endpoint directamente desde el navegador
- Ver la estructura de datos esperada
- Copiar ejemplos de peticiones

### Cómo usarlo en tu proyecto

En Node.js con Express:

```javascript
const swaggerUi = require('swagger-ui-express');
const swaggerDocument = require('./swagger.json');

app.use('/api-docs', swaggerUi.serve, swaggerUi.setup(swaggerDocument));
```

Ahora visita `http://localhost:3000/api-docs` y tienes tu API documentada
e interactiva.

<Aclaracion pregunta="¿Tengo que escribir OpenAPI a mano?">
  No necesariamente. Hay herramientas que lo generan automáticamente:

  - **swagger-jsdoc**: lee comentarios en el código y genera OpenAPI
  - ** Postman**: puede exportar collection como OpenAPI
  - ** Insomnia**: también exporta a OpenAPI

  Pero entender el formato te ayuda a detectar errores y personalizar
  la documentación.
</Aclaracion>

## Mocks: programar sin backend

Un **mock** es una simulación de tu API. El frontend puede programar
usando respuestas falsas que coinciden con el contrato.

### Ejemplo con Mock Service Worker (MSW)

```javascript
// En el frontend, para desarrollo
import { setupServer } from 'msw/node';
import { http, HttpResponse } from 'msw';

const server = setupServer(
  http.get('/api/v1/tareas', () => {
    return HttpResponse.json({
      data: [
        { id: 1, titulo: 'Estudiar APIs', completada: false },
        { id: 2, titulo: 'Hacer el proyecto', completada: true }
      ],
      total: 2
    });
  })
);
```

Con esto, el frontend programa contra la API sin necesitar que el backend
exista. Cuando el backend esté listo, se retira el mock.

## Resumen en 3 frases

1. **API-first** significa definir el contrato antes de escribir código:
   frontend y backend trabajan en paralelo contra el mismo documento.
2. **OpenAPI** es el formato estándar para documentar APIs; herramientas
   como Swagger UI lo convierten en documentación interactiva.
3. Los **mocks** permiten al frontend programar sin esperar al backend,
   simulando respuestas que cumplen el contrato.
