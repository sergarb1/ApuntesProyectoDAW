> 🗺️ **Estás en:** 🔧 **U1 · Evolucionar la arquitectura** → Índice

PI2 empieza con una verdad incómoda: **el código de PI1 no es la base
sólida que necesitas**. Pero no todo está perdido. Esta unidad te enseña
a transformar ese desorden en algo manejable, sin romper lo que ya
funciona. Es el momento de crecer como equipo técnico.

## Competencias que trabajas

| Competencia | Descripción |
|------------|-------------|
| **CG1** | Capacidad para evolucionar y mantener software existente |
| **CE1** | Refactorizar y mejorar código existente |
| **CE7** | Documentar la evolución del proyecto |

## Objetivos de esta unidad

Al terminar U1 sabrás:

1. Identificar y clasificar la deuda técnica de tu proyecto
2. Refactorizar código sin romper funcionalidad existente
3. Tomar decisiones técnicas justificadas (framework, API, BD)
4. Organizar el código en una estructura de carpetas modular
5. Usar Git de forma profesional con branching y versionado
6. Documentar la arquitectura para que otros la entiendan
7. Priorizar dónde gastar tiempo en mejorar el código
8. Aplicar un checklist completo antes de cada sprint

<Aclaracion pregunta="¿Por qué empezar PI2 por arquitectura y no por código?">
  Porque PI2 es **evolucionar**. Si la base está mal, cada función nueva
  amplifica el desorden. Una hora invirtiendo en estructura y decisiones
  te ahorra diez horas de debugging después. La arquitectura no es
  burocracia: es el plano que evita que la casa se caiga.
</Aclaracion>
