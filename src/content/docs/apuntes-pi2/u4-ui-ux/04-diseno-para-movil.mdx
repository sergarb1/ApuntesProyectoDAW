## La idea en una frase

> Más del 60% del tráfico web viene de dispositivos móviles. Si tu app
> no funciona en móvil, no funciona a secas.

## Mobile-first: el enfoque correcto

**Mobile-first** significa que diseñas primero para la pantalla más
pequeña (el móvil) y después añades complejidad para pantallas mayores.
Es al revés de lo que hace la mayoría: diseñar para el ordenador y
luego "adaptar" al móvil.

### Por qué mobile-first

| Enfoque | Problema |
|---------|----------|
| Desktop-first | El diseño de escritorio no cabe en móvil. Adaptar es quitar cosas. |
| Mobile-first | El diseño base es limpio. Añadir es enriquecer. |

Si empiezas por lo esencial (lo que cabe en una pantalla pequeña),
luego ampliar es fácil. Si empiezas por todo, recortar es doloroso.

### Cómo funciona en la práctica

```css
/* Base: móvil (una columna) */
.card-grid {
  display: grid;
  grid-template-columns: 1fr;
}

/* Tablet: dos columnas */
@media (min-width: 768px) {
  .card-grid {
    grid-template-columns: repeat(2, 1fr);
  }
}

/* Desktop: tres columnas */
@media (min-width: 1024px) {
  .card-grid {
    grid-template-columns: repeat(3, 1fr);
  }
}
```

## Diseño responsive

Responsive no es "que se vea bien en todo". Es que **el layout se adapta
automáticamente** al tamaño de pantalla sin romperse ni necesitar
scroll horizontal.

### Los tres puntos de ruptura habituales

| Punto | Ancho | Dispositivo típico |
|-------|-------|---------------------|
| Móvil | &lt; 768px | iPhone, Android |
| Tablet | 768px - 1024px | iPad, tablets Android |
| Desktop | &gt; 1024px | Portátil, monitor |

### Qué cambia entre pantallas

| Elemento | Móvil | Tablet | Desktop |
|----------|-------|--------|---------|
| Navegación | Menú hamburguesa | Menú horizontal o mixto | Menú horizontal completo |
| Card grid | 1 columna | 2 columnas | 3+ columnas |
| Tablas | Scroll horizontal o cards apiladas | Tabla completa | Tabla completa |
| Formularios | Campos a pantalla completa | Dos columnas | Tres columnas |

## Targets táctiles: dedos, no ratones

En móvil, el usuario interactúa con los dedos, no con un cursor de
2 píxeles. Los elementos interactivos deben tener un tamaño mínimo
de **44x44 píxeles** (recomendación de Apple) o **48x48 dp** (Google).

### Común vs correcto

| Elemento | Mal | Bien |
|----------|-----|------|
| Botón | 30x20px, texto pequeño | 48x44px, texto legible |
| Enlace | Texto subrayado pegado a otro | Espaciado entre enlaces, área de toque amplia |
| Icono | 16x16px | 44x44px con padding |
| Checkbox | 12x12px | 24x24px con label |

<Aclaracion pregunta="¿Qué pasa si no hago diseño responsive?">
  El tribunal puede acceder a tu app desde su móvil o tablet. Si la
  app no se adapta, la evaluarán como si tuviera errores de layout.
  En un mundo donde la mayoría del tráfico es móvil, no tener
  responsive es como tener una tienda sin puerta.

  Además, muchos profesores revisan los proyectos desde el móvil
  antes de la presentación. Primera impresión = todo.
</Aclaracion>

## Errores comunes en diseño móvil

| Error | Por qué está mal | Solución |
|-------|------------------|----------|
| Scroll horizontal | El contenido se sale de la pantalla | `overflow-x: hidden` y layouts flexibles |
| Texto demasiado pequeño | No se lee sin hacer zoom | Mínimo 16px base, usar rem |
| Botones demasiado juntos | Clics accidentales | Espaciado mínimo de 8px entre elementos |
| Tabla ancha | Se sale de la pantalla | Scroll horizontal o convertir a cards |
| Imágenes fijas | No se adaptan al ancho | `max-width: 100%; height: auto` |
| Fixed width en contenedores | No caben en pantalla pequeña | Usar porcentajes, max-width con container queries |

## Caso práctico

<CasoPractico titulo="De desktop-first a mobile-first en una tarde">

  Un equipo tenía una aplicación de AppointmentManager que solo se
  veía bien en desktop. El tribunal la abrió en móvil y fue un desastre:
  el formulario de Appointment necesitaba scroll horizontal, los botones
  eran demasiado pequeños, y el menú estaba oculto sin botón hamburguesa.

  **Cambios realizados (3 horas):**

  1. **Menú**: del menú horizontal oculto en móvil a un botón hamburguesa
     que despliega un menú vertical con los enlaces principales
  2. **Formulario**: de 3 columnas fijas a 1 columna en móvil, 2 en
     tablet, 3 en desktop. Cada campo a ancho completo en móvil
  3. **Botones**: de 30px a 48px de altura, con padding generoso
  4. **Tabla de datos**: en móvil se convierte en cards apiladas, en
     tablet y desktop se muestra como tabla con scroll horizontal
  5. **Imágenes**: todas con `max-width: 100%` y `height: auto`

  **Resultado**: la app se veía bien en cualquier dispositivo. El
  tribunal la probó en un iPhone y todo funcionó correctamente.

  **Lección**: mobile-first no es más trabajo. Es trabajo diferente.
  Y el resultado es una app que funciona para todos.
</CasoPractico>

## Mini-chequeo

**Pregunta 1.** ¿Cuál es el tamaño mínimo recomendado para un target
táctil?
A) 20x20px · B) 32x32px · C) 44x44px

**Pregunta 2.** ¿Qué enfoque es correcto para diseño responsive?
A) Desktop-first: diseñar para el ordenador y adaptar al móvil ·
B) Mobile-first: diseñar para el móvil y ampliar para pantallas mayores ·
C) No importa el orden, solo usar media queries

<details>
<summary>...Respuestas...</summary>

1. **C**. 44x44px (Apple) o 48x48dp (Google). Es el tamaño mínimo para
   que un dedo pueda pulsar un elemento sin error.
2. **B**. Mobile-first empieza por lo esencial y añade complejidad.
   Es más fácil ampliar que recortar.

</details>

## Resumen en 3 frases

1. Más del 60% del tráfico es móvil: si tu app no funciona en móvil,
   no funciona a secas.
2. Mobile-first significa diseñar primero para lo pequeño y ampliar
   después. Es más fácil que intentar recortar un diseño de escritorio.
3. Los targets táctiles deben tener mínimo 44x44px, y los layouts
   deben adaptarse sin scroll horizontal.

> 🐛 **Vocabulario rápido**

| Término | Idea general |
|---|---|
| **Mobile-first** | Diseñar para la pantalla pequeña primero y ampliar después |
| **Responsive** | Layout que se adapta automáticamente al tamaño de pantalla |
| **Media queries** | Reglas CSS que se activan según el ancho de pantalla |
| **Target táctil** | Área mínima que un dedo debe poder pulsar con precisión |
| **Breakpoint** | Punto de ruptura donde el layout cambia |
