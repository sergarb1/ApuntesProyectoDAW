## La idea en una frase

> Desplegar es el momento en que tu app pasa de funcionar en tu
> máquina a funcionar en el mundo real. Y el mundo real es diferente.

## Los pasos reales del despliegue

### Paso 1: Conectar el repositorio

En la plataforma de despliegue (Vercel, Render, Netlify), conecta
tu repositorio de GitHub:

1. Crea una cuenta en la plataforma
2. Haz clic en "New project" o "New site"
3. Selecciona "Import from GitHub"
4. Elige tu repositorio
5. La plataforma detecta automáticamente el framework

### Paso 2: Configurar la build

La plataforma necesita saber cómo construir tu app:

- **Framework**: Vite, Next.js, Astro, etc.
- **Build command**: `npm run build` (la mayoría lo detecta)
- **Output directory**: `dist` o `build` (depende del framework)
- **Install command**: `npm install` (normalmente automático)

### Paso 3: Definir variables de entorno

En la configuración de la plataforma, añade cada variable de
entorno que tu app necesite:

```
DB_HOST=mysql.example.com
DB_PORT=3306
DB_NAME=mi_app
DB_USER=admin
DB_PASSWORD=secreto123
API_KEY=sk-1234567890
```

### Paso 4: Desplegar

La mayoría de plataformas despliegan automáticamente al detectar
un push a `main`. Si no, haz clic en "Deploy" manualmente.

### Paso 5: Comprobar

Abre la URL que la plataforma te ha dado. Comprueba que:
- La app carga sin errores
- Los formularios funcionan
- La API responde
- No hay errores en la consola del navegador

## Errores comunes en el despliegue

### Error 1: "Module not found"

```
Error: Cannot find module 'express'
```

**Causa**: la dependencia está en `devDependencies` en vez de
`dependencies`. O no se ejecutó `npm install` correctamente.

**Solución**: comprueba que las dependencias de producción están
en `dependencies`.

### Error 2: "Build script not found"

```
Error: npm run build: script not found
```

**Causa**: el script se llama diferente en tu `package.json`.

**Solución**: comprueba el nombre exacto del script. Si se llama
`build:prod`, configura la plataforma para usar ese nombre.

### Error 3: Puerto no asignado

```
Error: listen EADDRINUSE: address already in use :::3000
```

**Causa**: tu app usa el puerto 3000, pero la plataforma asigna
un puerto diferente.

**Solución**: usa `process.env.PORT` en tu código:

```javascript
const PORT = process.env.PORT || 3000;
app.listen(PORT);
```

### Error 4: Variables de entorno no definidas

```
Error: DB_HOST is not defined
```

**Causa**: la variable de entorno no está configurada en la
plataforma.

**Solución**: ve a la configuración de la plataforma y añade
la variable.

### Error 5: Archivos que faltan

```
Error: ENOENT: no such file or directory
```

**Causa**: tu app busca archivos que no se subieron al repositorio.

**Solución**: comprueba que todos los archivos necesarios están
en el repositorio y en el `.gitignore` correcto.

## Cómo depurar un despliegue fallido

### Paso 1: Lee los logs

Cada plataforma tiene una sección de logs. En Render: Logs. En
Vercel: Function Logs. En Netlify: Deploys → selecciona el deploy
fallido.

Los logs muestran exactamente qué paso falló y por qué.

### Paso 2: Identifica el paso

El error normalmente indica el paso: "npm install falló", "npm run
build falló", "la app no arranca". Saber en qué paso falla te
ahorra tiempo.

### Paso 3: Reproduce el error en local

Intenta ejecutar el mismo comando en local. Si falla en local,
el problema es del código, no del despliegue.

### Paso 4: Busca la solución

Con el error exacto, busca en Stack Overflow, la documentación
de la plataforma o los issues de GitHub. Normalmente es un
problema conocido con solución sencilla.

<Aclaracion pregunta="¿Y si no encuentro la solución?">
  Pide ayuda. Los profesores, compañeros o la comunidad de
  la plataforma pueden ayudarte. Cuando pidas ayuda, incluye:

  1. El error exacto (copia y pega)
  2. Qué estabas haciendo (qué plataforma, qué workflow)
  3. Qué ya intentaste

  "Mi app no funciona en Render" no es una buena pregunta.
  "Render me da el error 'Cannot find module express' y ya
  comprobé que está en dependencies" sí lo es.
</Aclaracion>

## Desplegar paso a paso con Vercel

1. Ve a [vercel.com](https://vercel.com) y crea una cuenta
2. Haz clic en "New Project"
3. Importa tu repositorio de GitHub
4. Vercel detecta automáticamente Vite/Next.js/etc.
5. Configura las variables de entorno
6. Haz clic en "Deploy"
7. En 1-2 minutos, tu app está en producción
8. Copia la URL y compártela

## Desplegar paso a paso con Render

1. Ve a [render.com](https://render.com) y crea una cuenta
2. Haz clic en "New" → "Web Service"
3. Conecta tu repositorio de GitHub
4. Configura:
   - **Name**: nombre del proyecto
   - **Runtime**: Node
   - **Build Command**: `npm install && npm run build`
   - **Start Command**: `npm start`
5. Añade una base de datos si la necesitas (New → PostgreSQL)
6. Haz clic on "Create Web Service"
7. En 3-5 minutos, tu app está en producción

<CasoPractico titulo="El despliegue que parecía imposible">

  Un equipo llevaba 3 días intentando desplegar su app en Render.
  El error siempre era el mismo: la app arrancaba pero no
  respondía.

  Después de hours de depuración, encontraron el problema: su
  app Express escuchaba en `localhost`, pero Render asigna un
  puerto automático. La app nunca podía recibir conexiones.

  La solución fue una línea:

  ```javascript
  const PORT = process.env.PORT || 3000;
  app.listen(PORT, '0.0.0.0');
  ```

  `0.0.0.0` le dice al servidor que escuche en todas las
  interfaces de red, no solo en localhost. En 5 minutos
  corrigieron el código, hicieron push, y la app funcionó.

  **Lección**: el despliegue falla por detalles pequeños que
  en local no importan. Lee los logs, entiende el error y no
  pierdas la paciencia.
</CasoPractico>

## Mini-chequeo

**Pregunta 1.** ¿Qué haces primero cuando el despliegue falla?
A) Reescribes todo el código · B) Lees los logs de la plataforma
para identificar el error · C) Cambias de plataforma

**Pregunta 2.** ¿Por qué tu app no funciona en producción si
funciona en local?
A) Porque el servidor es más lento · B) Porque producción tiene
diferentes variables de entorno, puertos y configuración · C) Porque
GitHub tiene un bug

<details>
<summary>...Respuestas...</summary>

1. **B**. Los logs muestran exactamente qué falló. Leerlos es el
   primer paso para diagnosticar cualquier problema de despliegue.
2. **B**. Producción es un entorno diferente: el puerto puede ser
   distinto, las variables de entorno pueden no estar definidas y
   la configuración de red es diferente.

</details>

## Resumen en 3 frases

1. Desplegar implica conectar el repositorio, configurar la build,
   definir variables de entorno y comprobar que funciona.
2. Los errores más comunes son dependencias faltantes, puertos
   incorrectos y variables de entorno sin definir.
3. Cuando falle, lee los logs: te dicen exactamente qué paso
   y por qué.
