## La idea en una frase

> Docker Compose es como un director de orquesta: coordina varios
> contenedores para que toquen juntos.

## Qué es Docker Compose

Docker Compose es una herramienta que define y ejecuta **múltiples
contenedores** con un solo archivo de configuración. En vez de ejecutar
varios comandos `docker run` por separado, describes todos los servicios
en un archivo YAML y arrancas todo con una línea.

### Dónde encaja

- **Docker** gestiona contenedores individuales
- **Docker Compose** gestiona grupos de contenedores relacionados

Para un proyecto con frontend + backend + BD, Compose es la herramienta
correcta.

## Estructura de un docker-compose.yml

```yaml
version: '3.8'

services:
  frontend:
    build: ./frontend
    ports:
      - "5173:5173"
    depends_on:
      - backend

  backend:
    build: ./backend
    ports:
      - "3000:3000"
    environment:
      - DB_HOST=database
      - DB_PORT=3306
      - DB_NAME=mi_app
      - DB_USER=admin
      - DB_PASSWORD=secret123
    depends_on:
      - database

  database:
    image: mysql:8.0
    ports:
      - "3306:3306"
    environment:
      - MYSQL_ROOT_PASSWORD=rootpass
      - MYSQL_DATABASE=mi_app
      - MYSQL_USER=admin
      - MYSQL_PASSWORD=secret123
    volumes:
      - db_data:/var/lib/mysql

volumes:
  db_data:
```

## Explicación servicio por servicio

### frontend

```yaml
frontend:
  build: ./frontend        # Construye desde el Dockerfile en ./frontend
  ports:
    - "5173:5173"          # Mapea puerto 5173 del host al contenedor
  depends_on:
    - backend              # Arranca después del backend
```

### backend

```yaml
backend:
  build: ./backend
  ports:
    - "3000:3000"
  environment:              # Variables de entorno
    - DB_HOST=database      # Nombre del servicio, no localhost
    - DB_PORT=3306
  depends_on:
    - database              # Arranca después de la BD
```

**Punto clave**: `DB_HOST=database` usa el **nombre del servicio**,
no `localhost`. Docker Compose crea una red interna donde los servicios
se comunican por nombre.

### database

```yaml
database:
  image: mysql:8.0         # Imagen de Docker Hub (no necesita Dockerfile)
  environment:
    - MYSQL_ROOT_PASSWORD=rootpass
    - MYSQL_DATABASE=mi_app
  volumes:
    - db_data:/var/lib/mysql  # Persiste los datos
```

El volumen `db_data` asegura que los datos no se pierdan si el
contenedor se detiene o elimina.

## La red interna

Docker Compose crea automáticamente una **red** donde todos los
servicios se comunican. Los servicios se llaman entre sí por su
nombre en el `docker-compose.yml`.

```
┌─────────────────────────────────────────┐
│            Red de Docker Compose        │
│                                         │
│  ┌──────────┐  ┌──────────┐  ┌────────┐ │
│  │ frontend │→ │ backend  │→ │  DB    │ │
│  │ :5173    │  │ :3000    │  │ :3306  │ │
│  └──────────┘  └──────────┘  └────────┘ │
│        ↑             ↑            ↑     │
│   Puerto        Puerto        Puerto    │
│   del host      del host      del host  │
└─────────────────────────────────────────┘
```

Los servicios se ven entre sí como si estuvieran en la misma máquina.
El frontend llama a `http://backend:3000`, no a `http://localhost:3000`.

## Comandos esenciales

```bash
docker-compose up              # Arrancar (foreground)
docker-compose up -d           # Arrancar (background)
docker-compose logs            # Ver logs
docker-compose logs backend    # Logs de un servicio
docker-compose down            # Detener todo
docker-compose down -v         # Detener y eliminar volúmenes
docker-compose up --build      # Reconstruir imágenes
docker-compose ps              # Ver contenedores activos
```

## Variables de entorno: tres formas

### 1. Directamente en el YAML

```yaml
environment:
  - DB_HOST=database
  - DB_PASSWORD=secret123
```

Simple pero inseguro: las contraseñas quedan en el archivo.

### 2. Desde un archivo .env

```yaml
environment:
  - DB_HOST=${DB_HOST}
  - DB_PASSWORD=${DB_PASSWORD}
```

Mejor: las credenciales no están en el YAML.

### 3. Usando un archivo .env por servicio

```yaml
services:
  backend:
    env_file:
      - ./backend/.env
```

La mejor opción para proyectos con varios servicios.

<Aclaracion pregunta="¿Qué pasa si no quiero subir las credenciales al repositorio?">
  Nunca subas `.env` al repositorio. Añade `.env` a `.gitignore` y sube
  un `.env.example` con las variables sin valores reales. Quien clone el
  repositorio lo copia a `.env` y rellena los valores.
</Aclaracion>

## Persistencia de datos

Los contenedores son **efímeros**: cuando los eliminas, pierdes los
datos. Para persistir datos, usa **volúmenes**:

```yaml
services:
  database:
    image: mysql:8.0
    volumes:
      - db_data:/var/lib/mysql

volumes:
  db_data:
```

Los volúmenes mantienen los datos incluso después de `docker-compose down`.
Solo se eliminan con `docker-compose down -v`.

<Aclaracion pregunta="¿Qué pasa si olvido el volumen?">
  Si no defines un volumen para la base de datos, cada vez que ejecutas
  `docker-compose down` pierdes todos los datos. Usa volúmenes siempre
  que necesites persistencia.
</Aclaracion>

## Ejemplo real: proyecto DAW completo

```yaml
version: '3.8'

services:
  frontend:
    build: ./frontend
    ports:
      - "5173:5173"
    depends_on:
      - backend

  backend:
    build: ./backend
    ports:
      - "3000:3000"
    environment:
      - DATABASE_URL=mysql://admin:secret123@database:3306/mi_app
      - NODE_ENV=development
    depends_on:
      - database

  database:
    image: mysql:8.0
    ports:
      - "3306:3306"
    environment:
      - MYSQL_ROOT_PASSWORD=rootpass
      - MYSQL_DATABASE=mi_app
      - MYSQL_USER=admin
      - MYSQL_PASSWORD=secret123
    volumes:
      - db_data:/var/lib/mysql
      - ./database/init.sql:/docker-entrypoint-initdb.d/init.sql

volumes:
  db_data:
```

Para arrancar: `docker-compose up --build`. Para detener:
`docker-compose down`.

## Mini-chequeo

**Pregunta 1.** ¿Cómo se comunican los servicios en Docker Compose?
A) Usando localhost · B) Usando el nombre del servicio en el YAML ·
C) Usando la dirección IP del contenedor

**Pregunta 2.** ¿Qué hace `docker-compose down -v`?
A) Detiene los contenedores · B) Detiene los contenedores y elimina
los volúmenes · C) Detiene los contenedores y elimina las imágenes

<details>
<summary>...Respuestas...</summary>

1. **B**. Docker Compose crea una red interna donde los servicios se
   llaman por su nombre. Si el servicio se llama `database`, el backend
   usa `database` como host, no `localhost`.
2. **B**. `down` detiene y elimina contenedores. `-v` añade la
   eliminación de volúmenes. Los datos persistentes se pierden.

</details>

## Resumen en 3 frases

1. Docker Compose coordina varios contenedores con un solo archivo YAML
   y un solo comando.
2. Los servicios se comunican por nombre, no por localhost. Usa `.env`
   para credenciales y volúmenes para datos persistentes.
3. `docker-compose up --build` arranca todo. `docker-compose down` lo
   detiene. Un solo comando, cero excusas.
