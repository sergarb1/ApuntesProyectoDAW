## El problema de los entornos

Tu aplicación funciona en tu ordenador porque tiene tu versión de
Node.js, tu base de datos local, tus variables de entorno y tus
archivos en rutas específicas. En otro ordenador todo eso puede ser
distinto. Y la aplicación se rompe.

La solución es **empaquetar** tu aplicación para que incluya todo lo
que necesita. Y la herramienta para ello es Docker.

## Contenedores: la solución moderna

Un contenedor Docker es como una **caja** que contiene tu aplicación
y todo lo que necesita para funcionar. Dentro de la caja, la aplicación
ve el mismo sistema operativo, las mismas versiones, la misma
configuración, independientemente de dónde se ejecute la caja.

## ¿Necesitas Docker?

Sí, si tu proyecto tiene más de un servicio (frontend + backend + BD),
quieres que funcione igual en cualquier máquina, o quieres desplegarlo
en la nube. No, si es un proyecto pequeño que solo usas tú.

## Variables de entorno

Toda configuración que cambie entre entornos debe ir en variables de
entorno: URL de la base de datos, claves de API, puerto del servidor,
modo debug o producción.

```
config/
├── default.js      # común a todos
├── development.js  # base de datos local, logs detallados
└── production.js   # base de datos remota, logs mínimos
```

<CasoPractico titulo="El proyecto que se desplegó y funcionó">

  Un equipo dedicó los últimos 10 días del proyecto a preparar el despliegue:
  crearon un Dockerfile para el backend, un docker-compose.yml con backend
  + frontend + MySQL, probaron en su ordenador, subieron a un VPS, y el
  día de la presentación abrieron la URL en el navegador del tribunal.
  Funcionaba.

  **Lección**: el despliegue no es un paso opcional al final. Es parte
  del proyecto. Dedicarle tiempo es tan importante como programar.
</CasoPractico>

## Checklist para tu despliegue

- [ ] He probado a arrancar el proyecto desde cero en una máquina limpia
- [ ] Las configuraciones están en variables de entorno
- [ ] Tengo un README con instrucciones de instalación claras
- [ ] Si uso Docker, el docker-compose.yml funciona en otra máquina
- [ ] Los puertos y rutas están configurados (no hardcodeados)
- [ ] Las dependencias están especificadas con versiones exactas
- [ ] He probado el proyecto en un navegador que no sea el mío
