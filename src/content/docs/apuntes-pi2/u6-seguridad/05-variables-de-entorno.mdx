## La idea en una frase

> Si un secreto está en el código, no es un secreto. Es un accidente
> esperando ocurrir.

## Qué son las variables de entorno

Las **variables de entorno** son pares de clave-valor que existen
fuera del código. Tu aplicación las lee durante la ejecución, pero
no están escritas en ningún archivo que se suba a Git.

### Ejemplo en Node.js

```javascript
// ❌ MAL — Secreto hardcodeado en el código
const API_KEY = "sk-1234567890abcdef";
const DB_URL = "mongodb://usuario:password@localhost:27017/miBase";

// ✅ BIEN — Secreto en variable de entorno
const API_KEY = process.env.API_KEY;
const DB_URL = process.env.DATABASE_URL;
```

## Cómo crear y usar variables de entorno

### 1. Archivo `.env`

Crea un archivo `.env` en la raíz de tu proyecto:

```env
# .env
DATABASE_URL=mongodb://usuario:password@localhost:27017/miBase
API_KEY=sk-1234567890abcdef
JWT_SECRET=mi-clave-secreta-super-segura
PORT=3000
```

### 2. Cargar con dotenv

```javascript
// Al inicio de tu aplicación
require('dotenv').config();

// Ahora puedes acceder a las variables
const dbUrl = process.env.DATABASE_URL;
const apiKey = process.env.API_KEY;
```

```bash
npm install dotenv
```

### 3. Nunca subir `.env` a Git

Añade `.env` a tu `.gitignore`:

```gitignore
# .gitignore
.env
.env.local
.env.*.local
```

Si ya lo subiste, borra el historial o rota todas las claves
inmediatamente. Git conserva el historial: borrar el archivo no basta.

### 4. Crear `.env.example`

Para que otros desarrolladores sepan qué variables necesitan:

```env
# .env.example
DATABASE_URL=mongodb://localhost:27017/miBase
API_KEY=tu-aqui-tu-api-key
JWT_SECRET=tu-clave-secreta
PORT=3000
```

Este sí se sube a Git. Es una plantilla sin valores reales.

## Qué no hardcodear NUNCA

| Secreto | Dónde aparece típicamente | Riesgo |
|---------|---------------------------|--------|
| Contraseña de base de datos | Configuración de conexión | Acceso completo a la BD |
| API keys | Llamadas a servicios externos | Consumo fraudulento, facturas |
| JWT secret | Generación de tokens | Falsificación de identidad |
| Tokens de acceso (OAuth) | Integraciones con Google, GitHub | Suplantación de identidad |
| Credenciales de email SMTP | Envío de correos | Spam desde tu servidor |
| Datos de pago | Pasarelas de pago | Robo económico |

### Lo que sí puedes hardcodear

- URLs de endpoints públicos
- Nombres de tablas o campos
- Configuración de desarrollo (puerto, modo debug)
- Versión de la aplicación

## Variables de entorno en producción

En desarrollo, usas un archivo `.env`. En producción, la plataforma
donde despliegues gestiona las variables de entorno de forma diferente:

| Plataforma | Cómo configurar variables |
|------------|--------------------------|
| **Vercel** | Settings → Environment Variables |
| **Netlify** | Site settings → Environment variables |
| **Render** | Environment → Environment Variables |
| **Heroku** | Settings → Config Vars |
| **GitHub Actions** | Secrets en la configuración del workflow |

La clave es la misma: **nunca en el código, siempre en la configuración
del entorno**.

## Caso práctico

<CasoPractico titulo="La key de Stripe que costó 200 euros">

  Un equipo desarrolló una tienda online para el proyecto intermodular.
  Para probar los pagos, usaron la API key de prueba de Stripe. Pero
  en un momento, por error, copiaron la key de producción en el archivo
  de configuración.

  El archivo se subió a GitHub (público). Un bot automatizado escaneó
  repositorios buscando keys de Stripe. En menos de 2 horas, había
  hecho transacciones de prueba por valor de 200 euros.

  El equipo recibió una alerta de Stripe. Tuvieron que revocar la key,
  rotar todas las credenciales y explicar lo que pasó.

  **Lección**: las API keys nunca van en el código. Ni en producción,
  ni en desarrollo, ni "solo por un momento".

</CasoPractico>

<Aclaracion pregunta="¿Qué pasa si mi .env tiene valores por defecto inseguros?">
  Si tu `.env` tiene valores débiles como `JWT_SECRET=secret` o
  `DB_PASSWORD=password`, no estás protegiendo nada. Los secretos
  deben ser:

  - **Largos**: al menos 32 caracteres
  - **Aleatorios**: no palabras comunes ni patrones predecibles
  - **Únicos**: no reutilices el mismo secreto entre proyectos

  Puedes generar secretos seguros con:

  ```bash
  node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
  ```
</Aclaracion>

## Errores comunes

### 1. Subir `.env` a Git

```bash
# Si ya lo subiste, no basta con borrarlo del disco
# Necesitas borrarlo del historial de Git
git filter-branch --force --index-filter \
  'git rm --cached --ignore-unmatch .env' \
  --prune-empty --tag-name-filter cat -- --all
```

O más fácil: rota todas las claves y empieza de nuevo.

### 2. `.env` en el frontend

Si tu frontend es SPA (React, Vue, Angular), las variables de entorno
del navegador son **públicas**. No guardes secretos en el frontend.

```javascript
// ❌ MAL — Esto es visible en el navegador
const API_SECRET = process.env.REACT_APP_API_SECRET;

// ✅ BIEN — Los secretos van en el backend
// El frontend solo necesita URLs públicas
const API_URL = process.env.REACT_APP_API_URL;
```

### 3. Hardcodear en docker-compose.yml

```yaml
# ❌ MAL
environment:
  - DB_PASSWORD=miPassword123

# ✅ BIEN
environment:
  - DB_PASSWORD=${DB_PASSWORD}
```

Usa variables del entorno del sistema o un archivo `.env` separado.

A) En el código fuente · B) En variables de entorno de la plataforma ·

<details>
<summary>...Respuestas...</summary>

1. **B**. El archivo `.env` contiene valores reales de secretos y nunca
   debe subirse a Git. `.env.example` es una plantilla sin valores
   reales y sí se sube.
2. **B**. En producción, los secretos se configuran en la plataforma
   de despliegue (Vercel, Netlify, Render, etc.), nunca en el código.

</details>

## Resumen en 3 frases

1. Los secretos (contraseñas, API keys, tokens) nunca van hardcodeados
   en el código: siempre en variables de entorno.
2. Usa un archivo `.env` en desarrollo y la configuración de la
   plataforma en producción.
3. Añade `.env` a `.gitignore` y crea `.env.example` como plantilla
   para otros desarrolladores.

> 🐛 **Vocabulario rápido**

| Término | Idea general |
|---|---|
| **Variable de entorno** | Par clave-valor fuera del código que la app lee en ejecución |
| **Hardcodear** | Escribir un valor fijo directamente en el código fuente |
| **`.env`** | Archivo que almacena variables de entorno localmente |
| **`.gitignore`** | Lista de archivos que Git debe ignorar |
| **Rotar credenciales** | Cambiar todas las claves comprometidas por nuevas |
