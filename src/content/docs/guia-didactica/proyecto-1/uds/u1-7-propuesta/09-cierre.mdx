## 🎯 Mini-chequeo final

Responde estas preguntas antes de seguir:

### Preguntas de comprensión

<details>
<summary>¿Cuáles son las 5 preguntas que responde una propuesta?</summary>

**Respuesta**: ¿Qué vamos a hacer? ¿Por qué? ¿Para quién? ¿Cómo? ¿Cuándo?

**Para qué sirve**: Para que tu propuesta cubra todo lo esencial.
</details>

<details>
<summary>¿Qué es el briefing y por qué leerlo es el primer paso?</summary>

**Respuesta**: El briefing es el encargo del profesor con requisitos, tecnologías, evaluación y fechas. Leerlo evita hacer un proyecto que no cumple los requisitos.

**Para qué sirve**: Para no trabajar en vano.
</details>

<details>
<summary>¿Cuáles son las 3 zonas del alcance?</summary>

**Respuesta**: Dentro del alcance (lo que haremos), fuera del alcance (lo que no haremos) y post-entrega (lo que nos gustaría pero no caben).

**Para qué sirve**: Para definir límites claros y evitar que el proyecto crezca sin control.
</details>

<details>
<summary>¿Cuáles son las 6 fases de un proyecto?</summary>

**Respuesta**: Propuesta, diseño, desarrollo, testing, documentación y presentación.

**Para qué sirve**: Para dividir el proyecto en partes manejables.
</details>

<details>
<summary>¿Cuáles son las 7 secciones de una propuesta completa?</summary>

**Respuesta**: Portada, introducción/justificación, objetivos, usuario objetivo, funcionalidades, tecnologías/metodología y cronograma/equipo.

**Para qué sirve**: Para que tu propuesta tenga todo lo que el tribunal espera.
</details>

<details>
<summary>¿Cuál es el error más común en propuestas?</summary>

**Respuesta**: Ser demasiado ambicioso: querer hacer más de lo que el tiempo y el equipo permiten.

**Para qué sirve**: Para ser realista desde el principio.
</details>

---

### Ejercicio práctico

**En 90 minutos, escribe tu propuesta completa:**

1. **Lee el briefing** (10 min): Extrae requisitos, tecnologías, fechas
2. **Genera ideas** (15 min): Usa SCAMPER o lluvia de ideas
3. **Selecciona la idea** (10 min): Evalúa con los 5 criterios
4. **Define el alcance** (10 min): Lista de funcionalidades P0, P1, P2
5. **Crea el cronograma** (10 min): Fases, hitos, deadlines
6. **Escribe la propuesta** (25 min): Usa la plantilla del ejemplo
7. **Revisa errores** (10 min): ¿Tienes los 7 errores? Corrígelos

**Si consigues escribir todo esto → tu propuesta está lista para entregar.**

## 📖 Vocabulario rápido

| Término | Definición |
|---------|-----------|
| **Propuesta** | Documento formal que define el alcance, objetivos y plan de un proyecto |
| **Briefing** | Encargo o documento de requisitos del proyecto |
| **MVP** | Mínimo Viable Product: versión más simple que cumple requisitos mínimos |
| **Alcance** | Frontera del proyecto: qué entra, qué no y qué queda para después |
| **Hito** | Punto de control donde se verifica que todo va bien |
| **SCAMPER** | Técnica de brainstorming: Sustituir, Combinar, Adaptar, Modificar, Poner en otro uso, Eliminar, Revertir |
| **Cronograma** | Plan temporal del proyecto con fases, hitos y deadlines |
| **Estimación** | Predicción del tiempo necesario para completar una tarea |
| **Plan B** | Alternativa preparada para cuando algo sale mal |
| **Viabilidad** | Capacidad real de hacer algo con los recursos disponibles |

## 🚀 Cheat sheet: acciones rápidas con opencode

| Tarea | Prompt |
|-------|--------|
| **Analizar briefing** | `Analiza este briefing y lista: requisitos funcionales, no funcionales, restricciones de tiempo y criterios de evaluación` |
| **Generar ideas** | `Genera 15 ideas de proyectos frontend-only (Vue + Tailwind) que resuelvan problemas en el ámbito educativo` |
| **Evaluar idea** | `Evalúa esta idea [descripción] con criterios: viabilidad, originalidad, utilidad, esfuerzo. Dame una puntuación del 1 al 5` |
| **Escribir justificación** | `Escribe una justificación de 150 palabras para un proyecto de [descripción] que resuelve [problema]` |
| **Cronograma** | `Crea un cronograma de 6 semanas para un proyecto de [descripción] con 5 features. Incluye hitos semanales` |
| **Revisar propuesta** | `Revisa esta propuesta y dime: ¿qué secciones faltan? ¿Hay errores comunes? ¿Es realista el cronograma?` |

## 💡 Consejo para el siguiente punto

Si todavía no tienes claro cómo empezar tu propuesta:

1. **Lee el briefing otra vez** — extrae cada requisito
2. **Haz brainstorming** — genera 20 ideas en 10 minutos
3. **Evalúa con la tabla** — puntuación del 1 al 5
4. **Escribe la justificación** — el problema que resuelves
5. **Define 5 funcionalidades P0** — lo mínimo que necesitas

**No necesitas una propuesta perfecta. Necesitas una propuesta clara y realista.**

---

## ✅ Resumen en 3 frases

1. Una propuesta define **qué, por qué, para quién, cómo y cuándo** — en 7 secciones estructuradas.
2. Usa **técnicas de brainstorming** para generar ideas y **criterios objetivos** para seleccionar la mejor.
3. **Sé realista**: menos funcionalidades bien hechas que muchas a medias — y siempre ten un plan B.
