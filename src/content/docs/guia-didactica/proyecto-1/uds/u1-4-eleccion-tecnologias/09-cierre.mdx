## 🎯 Mini-chequeo final

Responde estas preguntas antes de seguir:

### Preguntas de comprensión

<details>
<summary>¿Cuáles son los 5 criterios de elección tecnológica?</summary>

**Respuesta**: 1) **Rendimiento** (velocidad y eficiencia), 2) **Curva de aprendizaje** (cuánto tardas en ser productivo), 3) **Ecosistema** (librerías y herramientas), 4) **Comunidad** (soporte y dudas), 5) **Mercado laboral** (oportunidades de empleo).

**Para qué sirve**: Para evaluar opciones con criterio objetivo, no por gusto personal.
</details>

<details>
<summary>¿Cuál es la diferencia entre SQL y NoSQL?</summary>

**Respuesta**: **SQL** (SQLite, PostgreSQL) organiza datos en tablas con relaciones y garantiza integridad. **NoSQL** (MongoDB) guarda documentos flexibles sin esquema fijo, priorizando flexibilidad.

**Para qué sirve**: Para elegir la base de datos adecuada según la estructura de tus datos.
</details>

<details>
<summary>¿Qué es un stack tecnológico?</summary>

**Respuesta**: El conjunto de tecnologías que trabajan juntas: lenguaje, framework, base de datos y despliegue. Ejemplo: Python + Flask + SQLite + GitHub Pages.

**Para qué sirve**: Para elegir un equipo coherente de tecnologías que encajen entre sí.
</details>

<details>
<summary>¿Qué es MVC y por qué importa?</summary>

**Respuesta**: **Modelo-Vista-Controlador**. Un patrón que separa la app en 3 capas: Modelo (datos), Vista (interfaz), Controlador (lógica). Separa responsabilidades para que el código sea más fácil de mantener.

**Para qué sirve**: Para organizar tu código y que cambiar el diseño no rompa la lógica.
</details>

<details>
<summary>¿Cuáles son las 4 partes de una justificación técnica?</summary>

**Respuesta**: 1) **Decisión** (qué elegiste), 2) **Criterio** (por qué con ese criterio), 3) **Alternativa descartada** (qué otra opción consideraste), 4) **Consecuencia** (qué ganas o pierdes).

**Para qué sirve**: Para argumentar tus decisiones con rigor, no con opiniones.
</details>

<details>
<summary>¿Qué stack es mejor para un proyecto escolar de 6 semanas?</summary>

**Respuesta**: **Python + SQLite + Django/Flask**. Curva de aprendizaje baja, cero configuración de base de datos, ORM y autenticación incluidos. Alternativa: JavaScript + SQLite + Express si ya conoces HTML/CSS.

**Para qué sirve**: Para ser productivo rápido sin sobrediseñar.
</details>

<details>
<summary>¿Qué tecnologías debo documentar en el template?</summary>

**Respuesta**: Las principales: **lenguaje backend, framework, base de datos y plataforma de despliegue**. No necesitas documentar HTML, CSS, Git ni editores (son estándar).

**Para qué sirve**: Para que tu justificación sea completa pero no burocrática.
</details>

**En 45 minutos, completa tu stack:**

1. **Elige stack** (10 min): Usa el flujo de decisión del punto 06

3. **Justifica** (15 min): Para cada tecnología, escribe criterio + alternativa + consecuencia

**Si consigues tener un `STACK.md` completo con justificación → has entendido la unidad.**

## 📖 Vocabulario rápido

| Término | Definición |
|---------|-----------|
| **Stack tecnológico** | Conjunto de tecnologías que trabajan juntas (lenguaje, framework, BD, despliegue) |
| **LAMP** | Linux + Apache + MySQL + PHP (stack clásico web) |
| **MERN** | MongoDB + Express + React + Node.js (stack JavaScript full-stack) |
| **MVC** | Modelo-Vista-Controlador: patrón de arquitectura para separar responsabilidades |
| **Monolito** | Arquitectura donde todo está en una sola aplicación |
| **Microservicios** | Arquitectura donde cada funcionalidad es un servicio independiente |
| **ORM** | Object-Relational Mapping: mapea objetos PHP/Python/Java a tablas SQL |
| **SQL** | Structured Query Language: lenguaje para consultar bases de datos relacionales |
| **NoSQL** | Bases de datos no relacionales (documentos, grafos, key-value) |
| **SQLite** | Base de datos SQL ligera, sin servidor, en un solo archivo |
| **PostgreSQL** | Base de datos SQL completa y profesional |
| **MongoDB** | Base de datos NoSQL por documentos (JSON) |
| **Curva de aprendizaje** | Tiempo que necesitas para ser productivo con una tecnología |
| **Ecosistema** | Librerías, frameworks y herramientas disponibles para una tecnología |
| **Justificación técnica** | Documento que argumenta decisiones tecnológicas con criterios objetivos |
| **Despliegue** | Proceso de publicar tu app en un servidor para que sea accesible |

## ✅ Resumen en 3 frases

1. Elegir tecnologías se basa en **5 criterios objetivos**: rendimiento, curva de aprendizaje, ecosistema, comunidad y mercado laboral.
2. Para un proyecto escolar de 6 semanas, **Python + SQLite + Flask/Django** es la opción más práctica: curva baja, cero configuración, productividad rápida.
3. **Documenta y justifica** tu stack en `STACK.md`: decisión + criterio + alternativa + consecuencia. Te toma 30 minutos y te ahorra semanas de dudas.
