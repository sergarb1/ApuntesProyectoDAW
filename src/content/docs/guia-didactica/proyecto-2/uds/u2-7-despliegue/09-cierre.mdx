## 🎯 Mini-chequeo final

Responde estas preguntas antes de seguir:

### Preguntas de comprensión

<details>
<summary>¿Qué es Docker y para qué sirve?</summary>

**Respuesta**: Docker empaqueta tu aplicación en un contenedor con todo lo que necesita (dependencias, configuración, sistema operativo) para que funcione igual en cualquier máquina. Elimina el problema de "en mi máquina funciona".
</details>

<details>
<summary>¿Qué es CI/CD y por qué importa?</summary>

**Respuesta**: CI/CD (Continuous Integration/Continuous Deployment) automatiza el proceso de test → build → deploy cada vez que haces push a main. Ahorra tiempo, reduce errores humanos y garantiza que el código desplegado siempre esté testeado.
</details>

<details>
<summary>¿Cuáles son las 3 estrategias de zero-downtime?</summary>

**Respuesta**: Rolling update (cambio gradual), blue-green (dos entornos idénticos) y canary (porcentaje pequeño de tráfico). Las tres evitan que el usuario vea errores durante el despliegue.
</details>

<details>
<summary>¿Cuál es el error más común de despliegue?</summary>

**Respuesta**: Variables de entorno no configuradas. La app funciona en local con `.env` pero en producción esas variables no existen. Solución: configurarlas en la plataforma.
</details>

<details>
<summary>¿Qué debes hacer después de desplegar?</summary>

**Respuesta**: Verificar que la URL carga, el login funciona, los CRUDs principales funcionan, los formularios envían datos y los logs se generan correctamente.
</details>

### Ejercicio práctico

**En 15 minutos, configura el despliegue de tu proyecto:**

1. Crea un `Dockerfile` básico (si tu proyecto lo necesita)
2. Configura un workflow de GitHub Actions para test + build
3. Elige una plataforma (Vercel para frontend, Render para Full-Stack)
4. Despliega y verifica que funciona
5. Documenta el proceso con la plantilla del punto 08

**Si consigues desplegar tu app y acceder a ella desde internet → has entendido la unidad.**

## 📖 Vocabulario rápido

| Término | Definición |
|---------|-----------|
| **Dockerfile** | Archivo de instrucciones para construir una imagen Docker |
| **Contenedor** | Caja aislada que ejecuta tu aplicación con todo lo que necesita |
| **CI/CD** | Continuous Integration / Continuous Deployment: automatización de build y deploy |
| **Workflow** | Pipeline de CI/CD definido en YAML |
| **Zero-downtime** | Despliegue sin interrupciones de servicio |
| **Rolling update** | Cambio gradual de versiones |
| **Blue-green** | Dos entornos idénticos, uno activo y uno en espera |
| **Canary** | Despliegue a un porcentaje pequeño de tráfico primero |
| **Rollback** | Volver a la versión anterior del despliegue |

## 💡 Consejo para el siguiente punto

Si vas a monitorizar tu app desplegada:

1. Empieza por **logs básicos** (punto 01 de UD 2.8)
2. Añade **métricas simples** como uptime y tiempo de respuesta
3. No necesitas Prometheus y Grafana para empezar: **console.log y un servicio de monitoreo básico bastan**

**Lo importante es empezar a observar, no tener el sistema perfecto.**

---

## ✅ Resumen en 3 frases

1. Docker **empaqueta tu app en contenedores** que funcionan igual en cualquier entorno.
2. CI/CD **automatiza** test → build → deploy con GitHub Actions, y las plataformas como Vercel y Render lo facilitan.
3. Después de desplegar, **verifica todo**: URL, funcionalidades, logs y rendimiento. Y ten un **plan de rollback** por si algo falla.
