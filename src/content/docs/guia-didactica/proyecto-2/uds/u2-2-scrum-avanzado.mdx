## 📬 La idea en una frase

> **SCRUM avanzado usa métricas para que mejores con datos, no con sensaciones.**

No es "me parece que voy bien". Es "mi velocity media es 13 puntos, necesito 2 sprints más".

## 🃏 El algoritmo

El proceso avanzado tiene 4 pasos:

1. **Estima con Planning Poker** — El equipo vota esfuerzo
2. **Mide con métricas** — Velocity, Burndown, Burnup
3. **Resuelve bloqueos** — Identifica y elimina obstáculos
4. **Mejora con retrospectivas** — Cambios concretos y medibles

## 👣 Paso a paso

### Paso 1: Estimación con Planning Poker

Cada miembro asigna un valor (puntos de historia) a cada tarea.
Si hay discrepancia, se debate y se vuelve a votar.

| Puntos | Significado |
|--------|-------------|
| 1 | Trivial |
| 2 | Pequeño |
| 3 | Medio |
| 5 | Grande |
| 8 | Muy grande, dividir |
| 13 | Enorme, dividir en subtareas |

### Paso 2: Métricas ágiles

#### Velocity (velocidad)

**Puntos completados por sprint**. Se usa para predecir cuánto tardarás:

| Sprint | Puntos completados |
|--------|-------------------|
| Sprint 1 | 12 |
| Sprint 2 | 15 |
| Sprint 3 | 14 |
| **Media** | **13.7** |

Si tienes 40 puntos pendientes, necesitarás ~3 sprints más.

#### Burndown Chart

Gráfico que muestra el progreso del sprint:

```
Puntos
  35 ┤●
  30 ┤ ●
  25 ┤  ●
  20 ┤   ●
  15 ┤    ●  ← Línea ideal
  10 ┤     ●
   5 ┤      ●
   0 ┤───────●─────
     D1  D2  D3  D4  D5  D6  D7
```

- **Encima de la línea ideal** → vas bien
- **Debajo** → riesgo de no completar el sprint

#### Burnup Chart

Alternativa que muestra **trabajo completado** vs **trabajo total**:

```
Puntos
  35 ┤─────────── Total
  30 ┤         ●
  25 ┤       ●
  20 ┤     ●
  15 ┤   ●
  10 ┤ ●
   5 ┤●
   0 ┤─────────── Completado
     D1  D2  D3  D4  D5  D6  D7
```

### Paso 3: Resolución de bloqueos

| Tipo de bloqueo | Solución |
|-----------------|----------|
| **Técnico** (no sé cómo hacerlo) | Buscar docs, preguntar, simplificar |
| **Dependencia** (necesito algo de otro) | Comunicar, priorizar, buscar alternativa |
| **Personal** (falta de tiempo) | Renegociar alcance, priorizar |
| **Ambigüedad** (no sé qué se espera) | Preguntar al profesor/cliente |

### Paso 4: Retrospectivas

#### Formato Kanban

```
┌─────────────┬─────────────┬─────────────┐
│  😊 BIEN     │  😟 MAL      │  💡 MEJORA   │
├─────────────┼─────────────┼─────────────┤
│ Commits     │ No estimé   │ Estimar     │
│ atómicos    │ bien        │ antes de    │
│             │             │ empezar     │
│ Revisé el   │ Me perdí    │ Usar tablero│
│ código      │ en el medio │ Kanban      │
└─────────────┴─────────────┴─────────────┘
```

#### Formato Start-Stop-Continue

| Start (empezar) | Stop (dejar) | Continue (seguir) |
|-----------------|--------------|-------------------|
| Estimar antes de programar | Cambiar de tarea constantemente | Commits atómicos |
| Hacer code review | No documentar decisiones | Revisar el backlog |

<Aclaracion pregunta="¿Y si me bloqueo todo un sprint?">
  No es un fracaso, es información. En la retrospectiva analiza por qué
  pasó y qué cambiarás. Los mejores equipos aprenden de sus bloqueos,
  no los esconden.
</Aclaracion>

## 📊 El análisis: ¿cuándo son útiles las métricas?

| Métrica | Cuándo usarla | Cuándo NO |
|---------|---------------|-----------|
| **Velocity** | Para predecir cuánto tardarás | Para comparar equipos |
| **Burndown** | Para ver si vas a tiempo en el sprint | Para castigar si vas lento |
| **Retrospectiva** | Siempre, al final de cada sprint | Nunca saltártela |

## ✅ Resumen en 3 frases

1. La **velocity** es tu brújula: cuántos puntos completas por sprint, eso es tu ritmo real.
2. El **Burndown** te dice si vas a tiempo: encima de la línea ideal vas bien, debajo tienes riesgo.
3. La **retrospectiva** es donde realmente mejoras: identifica qué cambiar y hazlo en el siguiente sprint.
