## 📬 La idea en una frase

> **Los entregables son la primera impresión del tribunal: organízalos bien para que tu trabajo brille.**

---

## Lista de entregables

### 1. Repositorio GitHub

| Aspecto | Qué esperar |
|---------|-------------|
| **README.md** | Descripción, stack, cómo ejecutar, URL de producción |
| **Estructura** | Carpetas organizadas (src/, tests/, docs/) |
| **Historial** | Commits claros con mensajes descriptivos |
| **Ramas** | Estrategia de branching documentada (GitFlow o similar) |
| **.gitignore** | Completo (node_modules, .env, dist) |
| **LICENSE** | Licencia del proyecto |

### 2. Código fuente

| Aspecto | Qué esperar |
|---------|-------------|
| **Backend** | API REST funcional con auth |
| **Frontend** | UI completa y funcional |
| **Tests** | Tests unitarios y/o de integración |
| **Configuración** | Variables de entorno documentadas |
| **Docker** | Dockerfile y docker-compose.yml (si aplica) |

### 3. Despliegue

| Aspecto | Qué esperar |
|---------|-------------|
| **URL de producción** | App accesible con HTTPS |
| **CI/CD** | GitHub Actions configurado |
| **Monitorización** | Logs y/o uptime monitoring |

### 4. Documentación

| Documento | Contenido |
|-----------|-----------|
| **README.md** | Instrucciones de instalación y uso |
| **Memoria** | Comparativa con Proyecto 1, decisiones técnicas |
| **Diagramas** | Diagrama C4 mínimo, diagrama ER |
| **Guía de usuario** | Cómo usar la aplicación |

### 5. Demo

| Aspecto | Qué esperar |
|---------|-------------|
| **Preparada** | Funciona sin errores |
| **Con datos** | Tiene datos de ejemplo cargados |
| **Probada** | La has probado en el navegador del tribunal |
| **Backup** | Tienes una versión local por si falla internet |

## Checklist de entrega

### Pre-entrega (1 semana antes)

- [ ] Todas las features Must funcionan
- [ ] Tests ejecutándose y pasando
- [ ] App desplegada con HTTPS
- [ ] README actualizado con instrucciones
- [ ] Memoria escrita
- [ ] Diagramas incluidos
- [ ] Demo probada en otro navegador
- [ ] Datos de demo cargados

### Día de la entrega

- [ ] Último commit con cambios finales
- [ ] Repositorio limpio (sin archivos innecesarios)
- [ ] URL de producción funciona
- [ ] Demo lista para presentar
- [ ] Backup local preparado

## Template de README

```markdown
# Nombre del Proyecto

Descripción breve del proyecto (1-2 frases).

## Stack tecnológico
- Frontend: [Framework + CSS]
- Backend: [Framework]
- BD: [Base de datos]
- Despliegue: [Plataforma]

## Cómo ejecutar

### Requisitos
- Node.js v20+
- npm

### Instalación
```bash
git clone https://github.com/usuario/proyecto.git
cd proyecto
npm install
cp .env.example .env
npm run dev
```

### Variables de entorno
| Variable | Descripción | Ejemplo |
|----------|-------------|---------|
| DATABASE_URL | URL de la BD | postgres://... |
| JWT_SECRET | Secreto JWT | mi-secreto |

## Despliegue
URL de producción: https://mi-app.vercel.app

## Autor
[Tu nombre] - [Tu email]
```

## Aclaracion: "¿Qué es la memoria?"

<Aclaracion icono="🤔" pregunta="¿Qué debo incluir en la memoria del proyecto?">
La memoria es un documento que explica **cómo y por qué** tomaste las decisiones técnicas. Incluye:

1. **Comparativa con Proyecto 1**: qué mejoraste y por qué
2. **Decisiones técnicas**: por qué elegiste ese stack, esos patrones
3. **Dificultades encontradas** y cómo las resolviste
4. **Lo que harías diferente** si empezaras de nuevo
5. **Futuras mejoras**: qué le añadirías con más tiempo

No es un documento técnico exhaustivo: es una reflexión de tu proceso.
</Aclaracion>

## Mini-chequeo

<details>
<summary>¿Cuáles son los 5 entregables principales?</summary>

Respuesta: 1) Repositorio GitHub limpio, 2) Código fuente funcional, 3) Despliegue con HTTPS, 4) Documentación completa, 5) Demo preparada.
</details>

<details>
<summary>¿Qué debe tener el README?</summary>

Respuesta: Descripción, stack tecnológico, instrucciones de instalación, variables de entorno, URL de producción y autor.
</details>

<details>
<summary>¿Qué es la memoria del proyecto?</summary>

Respuesta: Un documento que explica tus decisiones técnicas, la comparativa con Proyecto 1, las dificultades encontradas y las mejoras futuras.
</details>

---

## ✅ Resumen en 3 frases

1. Los 5 entregables son **repositorio limpio, código funcional, despliegue con HTTPS, documentación completa y demo preparada**.
2. El README debe tener **descripción, stack, instrucciones de instalación y URL de producción**.
3. Prepara la demo **una semana antes**: prueba en otros navegadores, carga datos de ejemplo y ten un backup local.
