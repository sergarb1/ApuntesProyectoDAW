## 🎯 Mini-chequeo final

Responde estas preguntas antes de seguir:

### Preguntas de comprensión

<details>
<summary>¿Qué hace bien la IA en desarrollo?</summary>

**Respuesta**: Genera código boilerplate, explica código existente, sugiere mejoras, convierte entre lenguajes y ayuda a aprender nuevas tecnologías. Es excelente para tareas repetitivas y patrones conocidos.
</details>

<details>
<summary>¿Qué hace MAL la IA?</summary>

**Respuesta**: No entiende tu negocio, no diseña arquitectura compleja, inventa dependencias, genera código con vulnerabilidades de seguridad y puede perder contexto en archivos largos.
</details>

<details>
<summary>¿Cuál es la fórmula de un buen prompt?</summary>

**Respuesta**: CONTEXTO + TAREA + RESTRICCIONES + EJEMPLO de resultado esperado. Sé específico, da contexto de tu proyecto y define el formato de salida.
</details>

<details>
<summary>¿Qué vulnerabilidades de seguridad debes buscar en código de IA?</summary>

**Respuesta**: SQL injection (queries con concatenación), XSS (innerHTML con input), secrets hardcodeados, autenticación débil (comparación directa de passwords) y CORS demasiado permisivo.
</details>

<details>
<summary>¿Por qué documentar el uso de IA?</summary>

**Respuesta**: Por transparencia (ser honesto con profesores/equipos), aprendizaje (reflexionar sobre qué funcionó), reusabilidad (guardar prompts efectivos) y ventaja competitiva (demostrar habilidades profesionales).
</details>

### Ejercicio práctico

**En 10 minutos, completa la plantilla del punto 12 con tu uso de IA:**

1. Lista las herramientas de IA que usaste
2. Estima el porcentaje de código generado con IA
3. Documenta 2-3 usos específicos con prompts
4. Anota qué funcionó y qué no
5. Guarda 2-3 prompts efectivos en tu prompt bank

**Si consigues documentar tu uso de IA de forma clara → has entendido la unidad.**

## 📊 Tabla resumen de la unidad

| Concepto | Idea clave |
|----------|------------|
| **Qué hace bien** | Boilerplate, explicaciones, aprendizaje |
| **Qué hace mal** | Negocio, arquitectura, seguridad |
| **Prompts** | CONTEXTO + TAREA + RESTRICCIONES + EJEMPLO |
| **Asistentes** | IDE (autocompletar) vs terminal (agentes); en el curso: opencode |
| **Agentes** | Ejecutan tareas de varios pasos: leen, editan, ejecutan, iteran |
| **Skills** | Instrucciones especializadas que el agente carga según la tarea |
| **opencode** | Agente de terminal, código abierto, capa gratuita (Zen y OpenRouter) |
| **Spec-Driven Dev** | Escribir la spec antes del código; openspec la estructura |
| **Testing** | Testea código de IA, usa IA para generar tests |
| **Seguridad** | Nunca hardcodees secrets, usa parámetros en queries |
| **Ética** | Sé transparente, entiende lo que generas, respeta licencias |
| **Errores** | Copiar sin leer es el error más peligroso |
| **Template** | Documenta tu uso para aprender y ser transparente |

## 📖 Vocabulario rápido

| Término | Definición |
|---------|-----------|
| **LLM** | Large Language Model — modelo de IA que genera texto y código |
| **Prompt** | Instrucción que le das a la IA para obtener un resultado |
| **Prompt engineering** | Arte de escribir prompts efectivos |
| **Asistente de IA** | Herramienta que usa un LLM para ayudarte a programar |
| **Agente de IA** | Asistente que ejecuta tareas de varios pasos (lee, edita, ejecuta) |
| **Skill** | Instrucciones especializadas que el agente carga según la tarea |
| **Spec-Driven Development** | Escribir la especificación antes del código y exigir que la cumpla |
| **openspec** | Herramienta que estructura specs y cambios con formato WHEN/THEN |
| **Hallucination** | Cuando la IA inventa datos, paquetes o funcionalidades que no existen |
| **Boilerplate** | Código repetitivo y estructurado que sigue un patrón |
| **OWASP** | Organización que lista las vulnerabilidades web más comunes |
| **Deepfake** | Contenido falso generado por IA que parece real |

## 💡 Consejo para el siguiente punto

Si vas a desplegar tu proyecto:

1. Usa la IA para generar el **Dockerfile** (punto 02 de UD 2.8)
2. Pide ayuda para configurar **GitHub Actions** (punto 03 de UD 2.8)
3. Recuerda: **revisa siempre** lo que la IA genere de seguridad

**La IA es tu copiloto en el despliegue, no el piloto.**

---

## ✅ Resumen en 3 frases

1. La IA es excelente para **código repetitivo y aprendizaje**, pero no entiende tu negocio ni tu contexto.
2. Usa la fórmula **CONTEXTO + TAREA + RESTRICCIONES + EJEMPLO** y siempre **revisa, testea y valida** el código generado.
3. Documenta tu uso de IA de forma **transparente y ética**: demuestra madurez profesional y te ayuda a aprender.
