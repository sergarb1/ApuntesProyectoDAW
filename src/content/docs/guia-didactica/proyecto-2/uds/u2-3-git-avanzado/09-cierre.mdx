## 🎯 Mini-chequeo final

### Preguntas de comprensión

<details>
<summary>¿Cuáles son las 5 ramas de GitFlow?</summary>

**main** (producción), **develop** (desarrollo integrado), **feature/** (nueva funcionalidad), **release/** (preparar versión), **hotfix/** (arreglo urgente).
</details>

<details>
<summary>¿Cuándo usar Trunk-Based vs GitFlow?</summary>

**Trunk-Based** para deploy continuo y equipos maduros. **GitFlow** para proyectos con versiones y equipos que necesitan más estructura.
</details>

<details>
<summary>¿Qué significan los marcadores de conflicto?</summary>

`<<<<<<< HEAD` = tu versión, `=======` = separador, `>>>>>>> feature` = la otra versión. Decides cuál usar y quitas los marcadores.
</details>

<details>
<summary>¿Qué verifica un hook pre-commit?</summary>

Depende de la configuración: **console.log**, **linter**, **secrets**, tests... Lo que tú le pidas.
</details>

<details>
<summary>¿Qué es CI/CD?</summary>

**CI**: ejecuta tests y build automáticamente en cada push. **CD**: despliega automáticamente cuando todo pasa. GitHub Actions lo hace todo.
</details>

<details>
<summary>¿Cuál es el formato de Conventional Commits?</summary>

`tipo(alcance): descripción`. Tipos: feat, fix, docs, style, refactor, test, chore, perf.
</details>

<details>
<summary>¿Qué buscar en un code review?</summary>

**Correctitud** (¿hace lo que debe?), **legibilidad**, **seguridad**, **rendimiento** y **mantenibilidad**. No revises estilo personal.
</details>

### Ejercicio práctico

**En 2 horas, configura tu workflow de Git:**

1. **Estructura** (15 min): Crea main y develop. Crea tu primer branch de feature
2. **Convenciones** (10 min): Añade un `GIT-WORKFLOW.md` con las reglas
3. **Hook** (20 min): Configura un pre-commit que ejecute el linter
4. **CI** (30 min): Crea `.github/workflows/ci.yml` con lint + test + build
5. **Code review** (15 min): Crea un PR y pide revisión a un compañero
6. **Prueba** (30 min): Haz push, verifica que CI funciona, merge el PR

**Si consigues tener CI ejecutándose en cada push → has entendido la unidad.**

## ✅ Resumen en 3 frases

1. **GitFlow** separa producción de desarrollo con 5 tipos de branches; **Trunk-Based** integra en main cada pocas horas con branches cortos.
2. Los **hooks** verifican calidad antes de commit, **Conventional Commits** hace el historial legible y **CI/CD** automatiza tests + build + deploy.
3. El **code review** no es un examen: es una conversación donde el autor explica y el revisor aprende. Ambos mejoran el código.
