## 📬 La idea en una frase

> **Los patrones creacionales te dan control sobre la creación de objetos: Singleton para una sola instancia, Factory para crear diferentes tipos, Builder para construir paso a paso.**

No crees objetos a lo loco. Crea con estrategia.

## Singleton: una sola instancia

### El problema

Necesitas que solo **exista UNA instancia** de una clase (configuración, logger, conexión a base de datos).

### La solución

```javascript
// Singleton en JavaScript
class Config {
  constructor() {
    if (Config.instance) {
      return Config.instance;
    }
    this.settings = {};
    Config.instance = this;
  }

  set(key, value) {
    this.settings[key] = value;
  }

  get(key) {
    return this.settings[key];
  }
}

// Uso
const config1 = new Config();
const config2 = new Config();

config1.set('theme', 'dark');
console.log(config2.get('theme')); // 'dark' (misma instancia)
console.log(config1 === config2);  // true
```

### Cuándo usarlo

| Caso | Ejemplo |
|------|---------|
| Configuración global | `Config.getInstance()` |
| Logger | `Logger.getInstance()` |
| Cache | `Cache.getInstance()` |

### Cuándo NO usarlo

- Cuando no necesitas una sola instancia
- Cuando dificulta los tests (estado global)

## Factory: crear objetos sin especificar la clase

### El problema

Necesitas crear diferentes tipos de objetos según la entrada, pero no quieres hacer `if/else` por todas partes.

### La solución

```javascript
// Factory en JavaScript
class NotificationFactory {
  static create(type, message) {
    switch (type) {
      case 'success':
        return new SuccessNotification(message);
      case 'error':
        return new ErrorNotification(message);
      case 'warning':
        return new WarningNotification(message);
      default:
        return new Notification(message);
    }
  }
}

class Notification {
  constructor(message) {
    this.message = message;
  }
  render() {
    return `<div>${this.message}</div>`;
  }
}

class SuccessNotification extends Notification {
  render() {
    return `<div class="success">${this.message}</div>`;
  }
}

class ErrorNotification extends Notification {
  render() {
    return `<div class="error">${this.message}</div>`;
  }
}

// Uso
const notif = NotificationFactory.create('success', 'Guardado correctamente');
notif.render(); // <div class="success">Guardado correctamente</div>
```

### Cuándo usarlo

| Caso | Ejemplo |
|------|---------|
| Diferentes tipos de notificaciones | Success, Error, Warning |
| Diferentes formatos de export | PDF, CSV, JSON |
| Diferentes tipos de usuario | Admin, Profesor, Alumno |

## Builder: construir objetos paso a paso

### El problema

Un objeto tiene **muchos parámetros opcionales** y el constructor se vuelve ilegible.

### La solución

```javascript
// Builder en JavaScript
class QueryBuilder {
  constructor() {
    this.table = '';
    this.conditions = [];
    this.orderBy = '';
    this.limit = null;
  }

  from(table) {
    this.table = table;
    return this; // permite encadenar
  }

  where(condition) {
    this.conditions.push(condition);
    return this;
  }

  order(field) {
    this.orderBy = field;
    return this;
  }

  take(limit) {
    this.limit = limit;
    return this;
  }

  build() {
    let query = `SELECT * FROM ${this.table}`;
    if (this.conditions.length) {
      query += ` WHERE ${this.conditions.join(' AND ')}`;
    }
    if (this.orderBy) {
      query += ` ORDER BY ${this.orderBy}`;
    }
    if (this.limit) {
      query += ` LIMIT ${this.limit}`;
    }
    return query;
  }
}

// Uso (encadenable)
const query = new QueryBuilder()
  .from('users')
  .where('age > 18')
  .where('active = true')
  .order('name')
  .take(10)
  .build();

// "SELECT * FROM users WHERE age > 18 AND active = true ORDER BY name LIMIT 10"
```

### Cuándo usarlo

| Caso | Ejemplo |
|------|---------|
| Queries SQL | Construir consultas complejas |
| Configuración compleja | Objetos con muchos parámetros opcionales |
| Objetos inmutables | Crear y no modificar después |

## Aclaración: "¿Cuándo uso Factory y cuándo Builder?"

<Aclaracion icono="🤔" pregunta="¿No hacen lo mismo Factory y Builder?">
No. La diferencia es clara:

| Factory | Builder |
|---------|---------|
| **Crea** un objeto de un tipo diferente | **Construye** un objeto complejo paso a paso |
| `NotificationFactory.create('error')` | `new QueryBuilder().from('users').where(...).build()` |
| Un solo paso | Múltiples pasos encadenados |
| Elige entre tipos | Construye con parámetros opcionales |

**Factory** = "necesito un coche rojo o azul" (elige tipo).
**Builder** = "necesito un coche con motor X, color Y y techo Z" (construye con opciones).
</Aclaracion>

## Mini-chequeo

<details>
<summary>¿Qué hace Singleton?</summary>

Asegura que solo **exista una instancia** de una clase. Todos los accesos devuelven la misma instancia.
</details>

<details>
<summary>¿Qué hace Factory?</summary>

**Crea diferentes tipos** de objetos según la entrada, sin usar if/else por todas partes. Es extensible: añadir un tipo nuevo es solo añadir un case.
</details>

<details>
<summary>¿Qué hace Builder?</summary>

**Construye objetos complejos paso a paso**, encadenando métodos. Ideal cuando el constructor tiene muchos parámetros opcionales.
</details>

---

## ✅ Resumen en 3 frases

1. **Singleton** asegura una sola instancia global: úsalo para configuración, logger o cache.
2. **Factory** crea diferentes tipos de objetos según la entrada: úsalo para notificaciones, exportaciones o tipos de usuario.
3. **Builder** construye objetos complejos paso a paso con encadenamiento: úsalo para queries, configuraciones o objetos con muchos parámetros opcionales.
