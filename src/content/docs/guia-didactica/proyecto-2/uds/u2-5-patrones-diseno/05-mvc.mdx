  **MVC** (Model-View-Controller) es el patrón arquitectónico más usado en
  desarrollo web. Separa la aplicación en 3 capas: **Model** (datos),
  **View** (interfaz) y **Controller** (lógica). Cada capa tiene su
  responsabilidad y no se mezcla con las demás.
</StoryIntro>

## 📬 La idea en una frase

> **MVC separa tu app en 3 capas: Model gestiona los datos, View muestra la interfaz, Controller coordina entre ambos. Cada capa hace una cosa y la hace bien.**

No mezcles lógica con interfaz. Separa y conquista.

---

## Las 3 capas de MVC

```
┌─────────────┐
│   View      │  ← Interfaz de usuario (HTML, CSS, componentes)
│   (Vista)   │
└──────┬──────┘
       │ Eventos (click, submit)
       ▼
┌─────────────┐
│ Controller  │  ← Lógica de negocio (qué hacer cuando el usuario actúa)
│ (Controlador│
└──────┬──────┘
       │ Datos
       ▼
┌─────────────┐
│   Model     │  ← Datos y reglas (estado, localStorage, validación)
│  (Modelo)   │
└─────────────┘
```

### Cada capa en detalle

| Capa | Responsabilidad | Ejemplo |
|------|----------------|---------|
| **Model** | Gestiona datos y estado | Lista de tareas, usuario actual, validación |
| **View** | Muestra la interfaz | Componente de lista, formulario, botones |
| **Controller** | Coordina Model y View | Maneja clicks, llama al Model, actualiza la View |

## Ejemplo: Lista de tareas con MVC

### Model (datos)

```javascript
// model/TaskModel.js
class TaskModel {
  constructor() {
    this.tasks = JSON.parse(localStorage.getItem('tasks') || '[]');
  }

  addTask(name) {
    const task = { id: Date.now(), name, done: false };
    this.tasks.push(task);
    this.save();
    return task;
  }

  toggleTask(id) {
    const task = this.tasks.find(t => t.id === id);
    if (task) {
      task.done = !task.done;
      this.save();
    }
  }

  deleteTask(id) {
    this.tasks = this.tasks.filter(t => t.id !== id);
    this.save();
  }

  save() {
    localStorage.setItem('tasks', JSON.stringify(this.tasks));
  }

  getAll() {
    return this.tasks;
  }
}
```

### View (interfaz)

```javascript
// view/TaskView.js
class TaskView {
  constructor(container) {
    this.container = container;
    this.onAdd = null;
    this.onToggle = null;
    this.onDelete = null;
  }

  render(tasks) {
    this.container.innerHTML = `
      <div class="task-form">
        <input type="text" id="task-input" placeholder="Nueva tarea">
        <button id="add-btn">Añadir</button>
      </div>
      <ul class="task-list">
        ${tasks.map(task => `
          <li class="${task.done ? 'done' : ''}">
            <input type="checkbox" ${task.done ? 'checked' : ''} data-id="${task.id}">
            <span>${task.name}</span>
            <button data-delete="${task.id}">×</button>
          </li>
        `).join('')}
      </ul>
    `;

    this.bindEvents();
  }

  bindEvents() {
    document.getElementById('add-btn').addEventListener('click', () => {
      const input = document.getElementById('task-input');
      if (input.value.trim()) {
        this.onAdd(input.value.trim());
        input.value = '';
      }
    });

    document.querySelectorAll('[data-id]').forEach(el => {
      el.addEventListener('change', () => {
        this.onToggle(parseInt(el.dataset.id));
      });
    });

    document.querySelectorAll('[data-delete]').forEach(el => {
      el.addEventListener('click', () => {
        this.onDelete(parseInt(el.dataset.delete));
      });
    });
  }
}
```

### Controller (lógica)

```javascript
// controller/TaskController.js
class TaskController {
  constructor(model, view) {
    this.model = model;
    this.view = view;

    // Conectar eventos de la View con el Model
    this.view.onAdd = (name) => this.addTask(name);
    this.view.onToggle = (id) => this.toggleTask(id);
    this.view.onDelete = (id) => this.deleteTask(id);

    // Render inicial
    this.render();
  }

  render() {
    this.view.render(this.model.getAll());
  }

  addTask(name) {
    this.model.addTask(name);
    this.render();
  }

  toggleTask(id) {
    this.model.toggleTask(id);
    this.render();
  }

  deleteTask(id) {
    this.model.deleteTask(id);
    this.render();
  }
}

// Uso
const model = new TaskModel();
const view = new TaskView(document.getElementById('app'));
const controller = new TaskController(model, view);
```

## MVC en frameworks modernos

| Framework | Model | View | Controller |
|-----------|-------|------|------------|
| **Vue** | Composition API / data | Template / SFC | Methods / computed |
| **React** | State / hooks | JSX components | Event handlers |
| **Angular** | Services | Templates | Components |
| **Laravel** | Eloquent models | Blade templates | Controllers |

En todos los casos, la **idea** es la misma: separar datos, interfaz y lógica.

---

## Aclaración: "¿Vue ya usa MVC?"

<Aclaracion icono="🤔" pregunta="¿Si uso Vue, ya estoy usando MVC?">
Sí, pero de forma implícita. Vue usa un patrón similar a MVC:

- **Model**: `ref()`, `reactive()`, datos del componente
- **View**: template HTML del `<template>`
- **Controller**: methods, computed, lifecycle hooks

Vue no se llama MVC formalmente, pero la **separación de responsabilidades** es la misma: datos, interfaz y lógica separados.
</Aclaracion>

## Mini-chequeo

<details>
<summary>¿Qué son las 3 capas de MVC?</summary>

**Model** (datos y estado), **View** (interfaz de usuario), **Controller** (lógica de negocio que coordina ambos).
</details>

<details>
<summary>¿Por qué separar en capas?</summary>

Para que **cambiar una capa no rompa las otras**. Cambias el diseño sin tocar la lógica. Cambias la lógica sin tocar los datos.
</details>

<details>
<summary>¿Vue usa MVC?</summary>

Implícitamente sí: **Model** = ref/reactive, **View** = template, **Controller** = methods/computed. La separación de responsabilidades es la misma.
</details>

---

## ✅ Resumen en 3 frases

1. **MVC** separa la app en 3 capas: **Model** (datos), **View** (interfaz), **Controller** (lógica de negocio).
2. La ventaja es la **separación de responsabilidades**: cambiar una capa no rompe las otras.
3. En frameworks como Vue, React o Angular, MVC se aplica de forma implícita: datos en el state, interfaz en el template, lógica en los methods.
